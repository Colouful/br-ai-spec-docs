# Product Roadmap

> 文档状态：V1 可执行版  
> 适用范围：`skill-q-platform`、`br-ai-spec`、`br-ai-spec-visual` 三仓协同路线图  
> 核心目标：按阶段推进，不盲目扩功能，优先打通“资产 → 安装 → 执行 → 观测 → 回流”的闭环。

---

## 1. 总体路线

```text
V1：Hub 资产中心 + 手动导入 + CLI 安装闭环
V2：Manifest 方案包 + 可视化配置器 + 安装前 diff
V3：运行态回流 + 质量评分 + 治理看板
V4：智能推荐 + 企业规则中心 + CI/CD 集成
```

核心判断：

> 现在最重要的不是继续堆页面，而是让 Manifest 成为三个仓库之间的主线。

---

## 2. V1：Hub 成为 br-ai-spec 的资产中心

### 2.1 目标

让 `br-ai-spec` 可以从 `skill-q-platform` 拉取 Skill / Rule / Manifest，并安装到业务项目。

### 2.2 范围

| 模块 | 内容 |
|---|---|
| Hub | Asset 统一模型、Manifest 初版、Export API |
| CLI | hub search / hub install / hub diff |
| Visual | 展示项目安装的 Manifest 和资产清单 |

### 2.3 必须完成

```text
1. Hub Asset 模型补全 kind / version / status / checksum。
2. Hub Manifest 模型落库。
3. Hub 提供 Manifest Export API。
4. br-ai-spec 新增 hub install。
5. br-ai-spec 生成 hub-lock.json。
6. Visual Collector 读取 hub-lock.json。
7. Visual 展示项目资产画像。
```

### 2.4 不做

```text
1. 不做复杂推荐。
2. 不做全量权限体系。
3. 不做企业多租户。
4. 不做自动 CI 阻断。
```

### 2.5 验收标准

```text
[ ] Hub 可以发布 react-standard-delivery@1.0.0
[ ] CLI 可以安装该方案包
[ ] 本地生成 hub-lock.json
[ ] Visual 可以展示 Manifest 和资产列表
[ ] Hub 能记录安装成功
```

---

## 3. V2：Manifest 方案包产品化

### 3.1 目标

让用户不是安装一个 Skill，而是安装一整套 AI 研发方案。

### 3.2 范围

| 模块 | 内容 |
|---|---|
| Hub | Manifest 配置器、方案包详情、版本管理、发布审核 |
| CLI | hub sync / hub upgrade / hub rollback |
| Visual | Drift 检测、过期提示、项目治理入口 |

### 3.3 必须完成

```text
1. Manifest 配置器支持选择 Skill / Rule / Role / Flow。
2. Manifest 安装前预览文件变更。
3. CLI 支持 sync / upgrade / rollback。
4. CLI 支持 light / standard / strict / audit-only。
5. Visual 支持本地 drift 检测。
6. Hub 支持 Manifest 版本历史。
```

### 3.4 验收标准

```text
[ ] 可以在页面组合一个 Manifest
[ ] 可以发布新版本
[ ] CLI 能展示版本 diff
[ ] CLI 能回滚到旧版本
[ ] Visual 能提示本地资产过期
```

---

## 4. V3：运行态回流与质量评分

### 4.1 目标

知道哪些 Skill / Rule / Manifest 真正有用，哪些资产导致阻塞和失败。

### 4.2 范围

| 模块 | 内容 |
|---|---|
| Visual | 运行态聚合、失败原因分类、资产使用统计 |
| Hub | 质量评分、安装量、成功率、风险画像 |
| CLI | 安装后自动上报基础结果 |

### 4.3 必须完成

```text
1. Visual 采集 run_started / asset_used / gate_blocked / run_completed。
2. Visual 脱敏聚合后回流 Hub。
3. Hub 展示 Manifest 成功率和安装项目数。
4. Hub 展示 Skill 使用频率和失败关联。
5. Hub 支持资产质量评分。
```

### 4.4 验收标准

```text
[ ] Hub 能看到每个 Manifest 的安装项目数
[ ] Hub 能看到运行成功率
[ ] Hub 能看到常见失败原因
[ ] Visual 能展示治理看板
[ ] 不上传源码和敏感配置
```

---

## 5. V4：企业治理与智能推荐

### 5.1 目标

从工具型平台升级为团队级 AI 工程治理平台。

### 5.2 范围

```text
1. 根据项目技术栈推荐 Manifest。
2. 根据失败原因推荐补充 Rule。
3. 根据资产评分推荐升级。
4. 与 CI/CD 集成，进行规范检查。
5. 支持团队、角色、权限、审核流。
6. 支持 OpenClaw 远程触发和审批。
```

### 5.3 验收标准

```text
[ ] 新项目能自动推荐方案包
[ ] 高风险资产默认不能安装
[ ] CI 可以检查 hub-lock.json 是否过期
[ ] 管理员可以看到团队接入率和风险项目
```

## 8. 优先级排序

| 优先级 | 功能 | 原因 |
|---|---|---|
| P0 | Manifest Export API | CLI 没有数据源无法安装 |
| P0 | hub install | 打通核心闭环 |
| P0 | hub-lock.json | Visual 和 diff 的基础 |
| P1 | Manifest 配置器 | 降低创建方案包成本 |
| P1 | hub diff | 企业接入必须知道文件影响 |
| P1 | Visual 资产画像 | 管理者要看接入结果 |
| P2 | 审核流 | 企业治理必备 |
| P2 | 运行效果回流 | 产品差异化 |
| P3 | 推荐系统 | 长期价值 |
