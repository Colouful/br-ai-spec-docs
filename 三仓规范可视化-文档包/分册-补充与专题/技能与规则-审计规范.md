# Skill Rule Audit Specification

> 文档状态：V1 可执行版  
> 所属项目：`skill-q-platform` 主导，`br-ai-spec` 安装前消费审计结果  
> 核心目标：为 Skill / Rule / Manifest 建立安全扫描、人工审核、风险分级和发布门禁。

---

## 1. 为什么需要审计

AI 工程资产和普通文档不同。Skill 可能指导 Agent 执行文件修改、命令执行、网络访问；Rule 可能改变团队开发约束；Manifest 可能一次性安装大量资产到业务项目。因此必须具备审计机制。

审计要解决的问题：

1. 防止恶意或错误 Skill 引导 Agent 执行危险操作。
2. 防止凭证、token、内网地址等敏感信息泄露。
3. 防止未审核资产被团队默认安装。
4. 让高风险资产有明确人工确认。
5. 为后续运行态评分和治理提供基础数据。

---

## 2. 资产状态流转

```text
draft 草稿
  ↓
submitted 待审核
  ↓
scanning 自动扫描中
  ↓
approved 审核通过
  ↓
published 已发布
  ↓
deprecated 已弃用
  ↓
archived 已归档
```

状态说明：

| 状态 | 是否可编辑 | 是否可安装 | 说明 |
|---|---|---|---|
| `draft` | 是 | 否 | 资产草稿 |
| `submitted` | 否 | 否 | 等待审核 |
| `scanning` | 否 | 否 | 自动安全扫描中 |
| `approved` | 否 | 否 | 审核通过但未发布 |
| `published` | 否 | 是 | 可被 Manifest 引用和 CLI 安装 |
| `deprecated` | 否 | 不推荐 | 已弃用，保留兼容 |
| `archived` | 否 | 否 | 归档隐藏 |

## 3. 风险等级

```ts
type RiskLevel = 'L0' | 'L1' | 'L2' | 'L3' | 'L4';
```

| 等级 | 名称 | 说明 | 发布策略 |
|---|---|---|---|
| `L0` | 安全 | 纯说明、纯规则、无敏感行为 | 可自动通过 |
| `L1` | 低风险 | 只读文件、生成文档、无外部访问 | 自动扫描通过后可发布 |
| `L2` | 中风险 | 写入项目文件、修改配置、生成命令 | 需要人工审核 |
| `L3` | 高风险 | Shell 执行、删除文件、访问外部服务 | 需要管理员审核，CLI 安装二次确认 |
| `L4` | 禁止 | 泄露凭证、破坏性命令、恶意行为 | 禁止发布 |

## 4. 自动扫描规则

### 4.1 文件结构扫描

Skill 必须满足：

```text
skill-name/
  SKILL.md
  可选：assets/
  可选：examples/
```

Rule 必须满足：

```text
rule-name/
  RULE.md
  可选：examples/
```

Manifest 必须满足：

```text
manifest.json
```

不允许出现：

```text
.env
.pem
.key
.id_rsa
node_modules/
.git/
```

---

### 4.2 敏感信息扫描

扫描内容：

| 类型 | 示例 |
|---|---|
| Token | `sk-xxx`、`ghp_xxx`、`xoxb-xxx` |
| 密钥 | `-----BEGIN PRIVATE KEY-----` |
| 数据库连接 | `mysql://user:pass@host/db` |
| 云服务凭证 | `AccessKeyId`、`SecretAccessKey` |
| 内网敏感地址 | 需要根据团队规则配置 |

发现敏感信息时：

- 默认标记为 `L4`。
- 阻断发布。
- 在页面提示具体文件和行号。

---

### 4.3 危险命令扫描

高危模式：

```text
rm -rf /
sudo rm
chmod 777
curl ... | sh
wget ... | sh
dd if=
mkfs
:(){ :|:& };:
```

中危模式：

```text
rm -rf node_modules
rm -rf dist
npm config set registry
pnpm install --force
```

处理策略：

| 结果 | 策略 |
|---|---|
| 高危 | L4，禁止发布 |
| 中危 | L3，必须管理员审核 |
| 低危 | L2，需要说明原因 |

---

### 4.4 外部访问扫描

扫描：

```text
http://
https://
curl
wget
fetch(
axios.
```

如果 Skill 明确要求调用外部服务，必须声明：

```json
{
  "permissions": [
    {
      "type": "network",
      "target": "https://api.example.com",
      "reason": "获取远程规则定义"
    }
  ]
}
```

未声明则不能通过审核。

## 5. 人工审核清单

审核人需要检查：

| 检查项 | 说明 |
|---|---|
| 资产定位是否清晰 | 名称、描述、适用场景是否明确 |
| 输入输出是否完整 | Agent 是否知道需要什么和产出什么 |
| 是否有越权行为 | 是否要求访问不必要文件或系统权限 |
| 是否和已有资产重复 | 是否可以复用已有 Skill / Rule |
| 是否破坏团队规范 | 是否和核心规则冲突 |
| 是否具备示例 | 是否有最小使用示例 |
| 是否可回滚 | 安装后是否可恢复 |

---

## 6. Manifest 审计

Manifest 审计不同于单资产审计，需要检查组合风险。

### 6.1 组合冲突检查

检查：

1. 是否同时引用两个互斥 Rule。
2. 是否有多个 Role 写入同一职责。
3. 是否 Flow 引用不存在的 Role。
4. 是否 Skill 依赖未包含。
5. 是否存在不同版本的同一资产。

### 6.2 安装影响检查

检查：

1. 会新增多少文件。
2. 会修改多少文件。
3. 是否覆盖已有 `.cursor` / `.claude` 命令。
4. 是否要求修改 `package.json`。
5. 是否要求开启 Git Hook。

## 7. 审计 API

### 7.1 提交审核

```http
POST /api/hub/assets/:id/submit
```

### 7.2 自动扫描

```http
POST /api/hub/assets/:id/scan
```

### 7.3 人工通过

```http
POST /api/hub/assets/:id/approve
```

请求：

```json
{
  "comment": "规则内容清晰，无敏感行为，允许发布。"
}
```

### 7.4 驳回

```http
POST /api/hub/assets/:id/reject
```

请求：

```json
{
  "reason": "检测到未声明的外部网络访问，请补充 permissions。"
}
```

## 8. CLI 安装前校验

`br-ai-spec hub install` 必须读取审计结果。

安装策略：

| 风险 | CLI 行为 |
|---|---|
| L0 / L1 | 正常安装 |
| L2 | 展示提示，可继续 |
| L3 | 二次确认，默认否 |
| L4 | 禁止安装 |

控制台示例：

```text
检测到高风险资产：shell-command-runner@1.0.0
风险等级：L3
原因：包含 Shell 执行指令，需要人工确认。

是否继续安装？输入 confirm 继续：
```

## 9. 审计日志表

```sql
CREATE TABLE hub_asset_audit_log (
  id VARCHAR(64) PRIMARY KEY,
  asset_id VARCHAR(64) NOT NULL,
  asset_version VARCHAR(32) NOT NULL,
  action VARCHAR(32) NOT NULL,
  risk_level VARCHAR(8),
  status VARCHAR(32) NOT NULL,
  findings_json JSON,
  operator_id VARCHAR(64),
  comment TEXT,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_asset_version (asset_id, asset_version),
  INDEX idx_status (status),
  INDEX idx_created_at (created_at)
);
```

---

## 10. 验收标准

1. 上传 Skill 后可以自动扫描 `SKILL.md`。
2. 上传 Rule 后可以自动扫描 `RULE.md`。
3. 发现敏感凭证时禁止发布。
4. L3 资产安装时 CLI 必须二次确认。
5. L4 资产不能被 Manifest 引用。
6. Manifest 发布前会检查资产状态和组合冲突。
7. 审计日志可追溯到审核人、审核时间、审核意见。
