# Manifest Package Design

> 文档状态：V1 可执行版  
> 所属项目：`skill-q-platform` 主导，`br-ai-spec` 消费，`br-ai-spec-visual` 展示  
> 核心目标：把零散 Skill / Rule / Role / Flow 组合成可安装、可审计、可升级、可回滚的团队级方案包。

---

## 1. Manifest 是什么

Manifest 是一个“AI 工程能力方案包”。它不是单个 Skill，也不是单个 Rule，而是一组资产的声明式组合。

例如：

```text
react-standard-delivery
├── role: requirement-analyst
├── role: frontend-implementer
├── role: code-guardian
├── skill: execute-task
├── skill: generate-test-plan
├── rule: react-code-style
├── rule: api-contract-rule
├── flow: prd-to-delivery
└── template: openspec-change-template
```

Manifest 的价值是：

1. 把团队规范沉淀为可安装方案。
2. 让新人不用理解全部底层资产，也能一键接入。
3. 让不同项目使用同一套标准。
4. 让后续升级、回滚、治理有明确版本依据。

## 5. Asset 组合规则

### 5.1 必须至少包含

| 类型 | 最低要求 |
|---|---|
| `rule` | 至少 1 个 |
| `skill` | 至少 1 个 |
| `role` | 至少 1 个 |
| `flow` | 至少 1 个主流程或轻量流程 |

### 5.2 推荐包含

| 类型 | 说明 |
|---|---|
| `template` | OpenSpec 模板、PRD 模板、测试模板 |
| `checklist` | 开发完成前检查清单 |
| `adapter` | Cursor / Claude / OpenClaw 命令适配 |
| `quality_gate` | 阻塞式质量门禁 |

## 6. Manifest 配置器页面设计

### 6.1 创建步骤

```text
步骤 1：填写基础信息
步骤 2：选择适用范围
步骤 3：选择 Role
步骤 4：选择 Skill
步骤 5：选择 Rule
步骤 6：选择 Flow / Scenario
步骤 7：配置安装策略
步骤 8：预览文件变更
步骤 9：提交审核或发布
```

### 6.2 页面字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | input | 是 | 中文名称 |
| `slug` | input | 是 | 英文唯一标识 |
| `description` | textarea | 是 | 说明用途 |
| `targetStacks` | multi-select | 是 | React / Vue / Next / 小程序等 |
| `targetIDEs` | multi-select | 是 | Cursor / Claude Code / OpenClaw 等 |
| `installMode` | radio | 是 | light / standard / strict / audit-only |
| `assets` | asset-picker | 是 | 资产选择器 |

---

## 7. 安装策略

```ts
type InstallMode = 'light' | 'standard' | 'strict' | 'audit-only';
```

| 模式 | 说明 | 适用场景 |
|---|---|---|
| `light` | 最小安装，只安装核心规则和入口命令 | 小团队、首次试点 |
| `standard` | 默认模式，安装完整 Skill / Rule / Role / Flow | 常规项目 |
| `strict` | 开启阻塞门禁、审计检查、强约束规则 | 核心系统、多人协作项目 |
| `audit-only` | 只扫描和提示，不修改项目 | 存量项目评估 |

## 10. 版本化规则

### 10.1 Patch

适用：

- 修改说明文案。
- 补充示例。
- 修复错别字。
- 不改变安装文件路径。
- 不改变流程语义。

CLI 策略：允许自动升级。

### 10.2 Minor

适用：

- 新增 Skill。
- 新增 Rule。
- 新增模板。
- 新增非阻塞式检查。

CLI 策略：展示 diff 后人工确认。

### 10.3 Major

适用：

- 删除资产。
- 改变 Flow 主链路。
- 修改阻塞门禁。
- 改变本地文件路径。

CLI 策略：必须人工确认，不允许静默升级。

## 11. 发布流程

```text
草稿 draft
  ↓
提交审核 submitted
  ↓
自动扫描 scanning
  ↓
审核通过 approved
  ↓
发布 published
  ↓
弃用 deprecated
  ↓
归档 archived
```

发布前必须校验：

1. Manifest 至少包含一个 Role、一个 Skill、一个 Rule、一个 Flow。
2. 所有必选资产必须是 `published` 状态。
3. 所有资产风险等级不得为 L4。
4. 版本号不得与已发布版本重复。
5. `checksum` 必须重新计算。

## 13. Visual 展示规则

`br-ai-spec-visual` 读取业务项目上报的 `hub-lock.json` 后，项目资产页展示：

| 字段 | 展示 |
|---|---|
| Manifest | 名称、版本、安装模式 |
| Assets | 类型、名称、版本、状态 |
| Drift | 本地修改、Hub 最新版本、差异数量 |
| Risk | 高风险资产、未审核资产 |
| Runtime | 使用次数、成功率、失败原因 |

---

## 14. 验收标准

1. 可以在 Hub 创建一个 Manifest。
2. 可以选择 Skill / Rule / Role / Flow 组合成方案包。
3. 可以发布 Manifest 并导出 JSON。
4. `br-ai-spec` 可以安装 Manifest 并生成 `hub-lock.json`。
5. `br-ai-spec-visual` 可以展示项目当前 Manifest。
6. Manifest 升级后 CLI 可以展示 diff。
7. Manifest 回滚后本地锁文件恢复到指定版本。
