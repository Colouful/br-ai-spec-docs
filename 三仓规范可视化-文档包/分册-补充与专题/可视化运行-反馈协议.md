# Visual Runtime Feedback Protocol

> 文档状态：V1 可执行版  
> 所属项目：`br-ai-spec-visual` 主导，`skill-q-platform` 接收回流，`br-ai-spec` 提供本地运行数据  
> 核心目标：让 Visual 不只是看板，而是把真实项目运行效果回流到 Hub，形成资产评分、推荐和治理闭环。

---

## 1. 背景

`br-ai-spec-visual` 当前负责多项目纳管、Runs / Changes、拓扑、规格视图、WebSocket 实时能力和 Collector 上报。Collector 会扫描：

```text
.ai-spec/
.agents/registry/
.omx/logs/
openspec/
```

这意味着 Visual 能够看到业务项目中的：

- 已安装 Manifest。
- 已安装 Skill / Rule / Role / Flow。
- 当前 run 状态。
- 历史 run。
- OpenSpec change。
- 本地 registry。
- 执行日志。

下一步需要把这些数据转化为 Hub 可消费的运行效果指标。

---

## 2. 总体数据流

```text
业务项目
  ↓ Collector 扫描
br-ai-spec-visual
  ↓ 聚合 / 清洗 / 脱敏
skill-q-platform
  ↓ 评分 / 推荐 / 治理
Manifest / Asset 质量画像
```

## 6. 回流到 Hub 的聚合指标

Visual 不应把完整业务代码、完整需求内容回传 Hub，必须先聚合和脱敏。

### 6.1 Manifest 指标

| 指标 | 说明 |
|---|---|
| `installProjectCount` | 安装项目数 |
| `runCount` | 总运行次数 |
| `successRunCount` | 成功运行次数 |
| `failedRunCount` | 失败运行次数 |
| `avgDurationMs` | 平均耗时 |
| `avgAutoFixCount` | 平均自动修复次数 |
| `blockCount` | 门禁阻断次数 |
| `rollbackCount` | 回滚次数 |

### 6.2 Asset 指标

| 指标 | 说明 |
|---|---|
| `usedRunCount` | 被多少 run 使用 |
| `successContributionCount` | 成功 run 中出现次数 |
| `failureCorrelationCount` | 失败 run 中出现次数 |
| `avgStageDurationMs` | 所在阶段平均耗时 |
| `commonFailureReasons` | 常见失败原因 |
| `projectCoverage` | 覆盖项目数 |

## 8. Visual 页面新增

### 8.1 项目资产画像页

路径：

```text
/workspaces/[workspaceId]/projects/[projectId]/assets
```

展示：

- 当前 Manifest 名称和版本。
- 安装模式。
- 资产列表。
- 本地漂移情况。
- 高风险资产。
- 过期资产。

### 8.2 运行效果页

路径：

```text
/workspaces/[workspaceId]/runtime-insights
```

展示：

- Manifest 成功率排行。
- Skill 使用频率排行。
- Rule 阻断次数排行。
- 常见失败原因。
- 项目接入趋势。

### 8.3 治理看板

路径：

```text
/workspaces/[workspaceId]/governance
```

展示：

- 未安装标准 Manifest 的项目。
- 使用过期资产的项目。
- 使用未审核资产的项目。
- 长时间无运行记录的项目。
- 高失败率 Manifest。

## 9. 隐私与脱敏规则

禁止回流：

```text
业务源码
完整需求正文
用户个人信息
接口密钥
.env 内容
数据库连接串
Cookie / Token
```

允许回流：

```text
资产 slug
资产版本
运行状态
阶段耗时
失败原因分类
门禁命中类型
文件 checksum
```

失败原因应分类，而不是直接上传原始异常全文。

示例：

```json
{
  "failureCategory": "missing-api-contract",
  "failureMessage": "接口契约缺失响应示例"
}
```

## 10. WebSocket 实时推送

Visual 继续通过 WebSocket 推送：

```text
project.asset.updated

```

## 11. 数据库表建议

### 11.1 `runtime_project_snapshot`

```sql
CREATE TABLE runtime_project_snapshot (
  id VARCHAR(64) PRIMARY KEY,
  workspace_id VARCHAR(64) NOT NULL,
  project_id VARCHAR(64) NOT NULL,
  manifest_slug VARCHAR(128),
  manifest_version VARCHAR(32),
  assets_json JSON,
  drift_json JSON,
  collected_at DATETIME NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_project (project_id),
  INDEX idx_manifest (manifest_slug, manifest_version)
);
```

### 11.2 `runtime_usage_metric`

```sql
CREATE TABLE runtime_usage_metric (
  id VARCHAR(64) PRIMARY KEY,
  project_id VARCHAR(64) NOT NULL,
  manifest_slug VARCHAR(128) NOT NULL,
  manifest_version VARCHAR(32) NOT NULL,
  period VARCHAR(16) NOT NULL,
  metrics_json JSON NOT NULL,
  calculated_at DATETIME NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_manifest_period (manifest_slug, manifest_version, period)
);
```

## 12. 验收标准

1. Collector 可以读取 `hub-lock.json`。
2. Visual 可以展示项目 Manifest 与资产列表。
3. Visual 可以识别本地 drift。
4. Visual 可以聚合运行成功率、失败率、耗时。
5. Visual 可以向 Hub 上报脱敏后的运行指标。
6. Hub 可以展示某个 Manifest 的安装项目数和运行成功率。
7. 全链路不上传源码和敏感配置。
