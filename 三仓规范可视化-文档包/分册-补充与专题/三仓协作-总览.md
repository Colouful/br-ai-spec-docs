# Three Repo Collaboration Overview

> 文档状态：V1 可执行版  
> 适用项目：`skill-q-platform`、`br-ai-spec`、`br-ai-spec-visual`  
> 核心目标：把三个仓库从“独立工具”收束为“AI 规范驱动研发操作系统”的一条完整产品链路。

---

## 1. 背景与目标

当前三个项目已经具备较清晰的雏形：

- `skill-q-platform`：当前是 Next.js + Prisma + MySQL 的 Skill / Rule 双轨资源站，已具备 Skills、Rules、统一搜索、榜单、ZIP 上传、在线编辑、本地 Skill / Rule 批量导入等能力。
- `br-ai-spec`：当前是 `@ex/ai-spec-auto` CLI，负责把 `.agents/rules`、`.agents/skills`、`.cursor`、`.claude`、`openspec`、`.ai-spec` 运行态等能力落到业务项目中，支撑 `/spec-start`、`/spec-update`、`/spec-status` 等 AI 规范驱动开发流程。
- `br-ai-spec-visual`：当前是面向 `ai-spec-auto` 的可视化与控制面，负责工作区、Runs / Changes、拓扑、规格视图、WebSocket 实时能力和 Collector 上报。

这次改造的目标不是再单独扩展某一个项目，而是形成闭环：

```text
Hub 资产生产 → CLI 项目安装 → 业务项目执行 → Visual 运行观测 → Hub 效果回流
```

---

## 2. 三仓总定位

| 仓库 | 产品定位 | 技术定位 | 不应该做什么 |
|---|---|---|---|
| `skill-q-platform` | AI 工程资产 Hub | 资产、Manifest、审核、版本、发布、安装记录、运行效果聚合 | 不直接执行业务项目任务；不维护业务项目本地状态机 |
| `br-ai-spec` | 项目级执行底座 / CLI | 安装、同步、diff、升级、回滚、生成本地 `.agents` / `.ai-spec` / `openspec` | 不做资产社区运营；不做复杂可视化看板 |
| `br-ai-spec-visual` | 团队控制台 / 运行观测面 | 多项目纳管、Collector、运行态、拓扑、治理看板、实时推送 | 不重新定义 Hub 资产模型；不作为资产源头 |

---

## 3. 统一产品主线

当前最需要统一的是产品口径：

> 这不是三个项目，而是一套面向团队的 AI 规范驱动研发操作系统。

具体产品主线如下：

1. 架构师或平台管理员在 `skill-q-platform` 创建资产，包括 Skill、Rule、Role、Flow、Scenario、Template、Adapter。
2. 架构师将资产组合成 Manifest 方案包，例如 `react-standard-delivery`、`vue3-component-library-governance`。
3. 普通开发者在业务项目中通过 `br-ai-spec` CLI 一键安装方案包。
4. CLI 将资产落到本地 `.agents/registry`、`.cursor`、`.claude`、`openspec` 等目录，并生成 `hub-lock.json`。
5. 开发者通过 `/spec-start`、`/spec-update`、`/spec-status` 执行规范驱动开发流程。
6. `br-ai-spec-visual` Collector 扫描 `.ai-spec`、`.agents/registry`、`.omx/logs`、`openspec`，将项目状态上报到控制台。
7. Visual 将安装状态、运行次数、失败原因、规则命中等数据回流到 Hub。
8. Hub 基于真实运行数据形成资产评分、方案推荐、风险治理和版本演进依据。

## 5. 核心集成对象

### 5.1 Asset

Asset 是 Hub 中的最小资产单元。

```ts
type AssetKind =
  | 'skill'
  | 'rule'
  | 'role'
  | 'flow'
  | 'scenario'
  | 'template'
  | 'adapter'
  | 'checklist'
  | 'quality_gate';
```

### 5.2 Manifest

Manifest 是方案包，是把多个资产组合成可安装方案的唯一事实源。

```ts
interface ManifestPackage {
  id: string;
  name: string;
  slug: string;
  version: string;
  targetStacks: string[];
  targetIDEs: string[];
  installMode: 'light' | 'standard' | 'strict' | 'audit-only';
  assets: ManifestAssetRef[];
  policies: InstallPolicy[];
}
```

### 5.3 hub-lock.json

`hub-lock.json` 是业务项目本地安装状态锁定文件，用于记录资产来源、版本、校验和、安装时间、安装模式。

建议路径：

```text
.agents/registry/hub-lock.json
```

## 6. 项目边界规则

### 6.1 `skill-q-platform` 边界

必须负责：

- Asset 创建、编辑、版本化、审核、发布、弃用、归档。
- Manifest 创建、配置、发布、导出。
- 资产安全扫描结果沉淀。
- 安装记录和运行效果聚合。
- 面向 CLI 提供稳定 API。

禁止负责：

- 直接修改业务项目文件。
- 直接执行 `/spec-start` 等本地流程。
- 重新实现 Visual 的多项目运行态看板。

### 6.2 `br-ai-spec` 边界

必须负责：

- Hub 登录、搜索、安装、同步、diff、升级、回滚。
- 将 Hub Manifest 转成本地目录结构。
- 校验本地资产与锁文件一致性。
- 输出清晰的中文控制台提示。
- 兼容当前 `init/update/check/uninstall` 主路径。

禁止负责：

- 管理资产审核流。
- 持久化全局安装统计。
- 提供复杂图表和团队治理页面。

### 6.3 `br-ai-spec-visual` 边界

必须负责：

- Collector 扫描并上报项目状态。
- 展示项目安装了哪个 Manifest、哪些资产、哪些版本。
- 展示运行态、历史 Run、Change、Topology。
- 将资产使用效果回流 Hub。

禁止负责：

- 重新创建一套 Asset / Manifest 标准。
- 直接编辑 Hub 资产源数据。
- 替代 CLI 进行安装。

## 8. 端到端验收链路

必须跑通以下场景：

```text
1. 在 skill-q-platform 新建资产：react-code-style-rule、frontend-implementer、execute-task-skill。
2. 创建 Manifest：react-standard-delivery@1.0.0。
3. 发布 Manifest。
4. 在业务项目执行：npx @ex/ai-spec-auto hub install react-standard-delivery --hub http://localhost:3000。
5. 本地生成 .agents/registry/hub-lock.json。
6. 本地生成或更新 .agents/rules、.agents/skills、.cursor、.claude、openspec。
7. 执行 /spec-start 产生运行态。
8. 使用 br-ai-spec-visual Collector 上报项目状态。
9. Visual 展示 Manifest、资产清单、Run 状态。
10. Hub 收到安装记录与运行效果回流。
```

## 9. 交付物清单

| 交付物 | 所属仓库 | 说明 |
|---|---|---|
| Asset 统一模型 | `skill-q-platform` | 支持 Skill / Rule / Role / Flow 等资产 |
| Manifest 管理页面 | `skill-q-platform` | 可视化组合方案包 |
| Manifest Export API | `skill-q-platform` | CLI 消费的标准出口 |
| Hub CLI 命令 | `br-ai-spec` | search / install / sync / diff / upgrade / rollback |
| hub-lock.json | `br-ai-spec` | 本地安装锁定文件 |
| 项目资产画像 | `br-ai-spec-visual` | 展示项目安装状态 |
| 运行态回流接口 | `br-ai-spec-visual` + `skill-q-platform` | 统计资产真实使用效果 |

## 10. 开发优先级

| 优先级 | 内容 | 原因 |
|---|---|---|
| P0 | Manifest 数据模型、导出 API、CLI install、hub-lock | 没有这些就没有闭环 |
| P1 | Manifest 配置器、安装前预览、Visual 资产画像 | 让方案包可用、可看、可验证 |
| P2 | 审核流、安全扫描、运行效果评分 | 企业级治理能力 |
| P3 | 推荐系统、团队治理看板、智能匹配方案包 | 产品差异化能力 |

---

## 11. 开发注意事项

1. 不要让三个仓库同时定义三套 Manifest 结构，必须以 Hub Contract 为准。
2. `br-ai-spec` 必须保留当前 `init/update/check/uninstall`，Hub 命令作为新增能力。
3. Visual 只能展示和回传，不应该成为资产源头。
4. 所有控制台提示、错误提示、页面提示统一使用中文。
5. 所有新增 API 必须具备版本字段，避免后续协议升级破坏兼容性。
