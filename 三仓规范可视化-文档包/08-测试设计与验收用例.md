# Test Design and Acceptance Cases

## 测试类型

单元测试：Manifest 校验、版本比较、依赖解析、checksum。接口测试：Asset / Manifest / Install / Runtime API。CLI 测试：install / sync / diff / upgrade / rollback。前端测试：页面渲染、表单校验、权限控制。集成测试：三仓闭环。

## 核心 E2E

1. Hub 创建 Asset。
2. Hub 创建 Manifest。
3. 添加资产到 Manifest。
4. 发布 Manifest v1.0.0。
5. 测试项目执行 CLI install。
6. 生成 `.agents/registry` 和 `hub-lock.json`。
7. Visual Collector 采集项目。
8. Visual 展示 Manifest 和资产版本。
9. Hub 看到安装记录。
10. 模拟 run，Visual 回流 runtime report。

## 通过标准

所有步骤成功；无未捕获异常；所有提示为中文；不破坏已有 Skill / Rule 功能；重复安装幂等；冲突不默认覆盖；失败可回滚。

## 回归范围

现有 Skill 列表、Rule 列表、上传能力、br-ai-spec 旧 init 命令、br-ai-spec-visual 原项目列表均不能受影响。
