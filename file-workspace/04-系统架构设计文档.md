# 系统架构设计文档

## 1. 架构目标
1. 支持 Demo-first 快速接入  
2. 保留 Team-ready 的扩展能力  
3. 让 Base 与 Visual 解耦协作  
4. 让 Collector 成为项目与平台之间的状态桥梁  
5. 支持后续扩展治理、控制与统计能力  

## 2. 总体架构分层

### 2.1 项目侧（Project Layer）
- 业务项目代码仓库
- BR AI Spec Base
- rules / skills / OpenSpec / `.ai-spec`
- IDE 命令入口

### 2.2 采集与同步层（Collector Layer）
- Collector CLI / 同步脚本
- 采集目录资产与运行态信息
- 推送到 Visual 服务端

### 2.3 平台服务层（Platform Service Layer）
- Visual Web Server
- 聚合接口
- 实时推送能力
- 接入管理能力
- 指标统计能力

### 2.4 展示与控制层（Console Layer）
- Dashboard
- Runs / Changes / Specs / Topology
- Workspace 管理
- 试点与指标视图


## 4. 核心组件说明

### 4.1 Base
部署在业务项目内，负责规范注入与本地交付流程支撑。

### 4.2 Collector
负责采集文件资产与运行态，并与平台建立同步关系。

### 4.3 Visual Server
负责承接 Collector 数据、聚合状态、提供页面 API、支撑 Dashboard 与其他视图。

### 4.4 Dashboard
负责将接入、运行、阻塞、收益、试点等信息转成管理者与开发者都能理解的页面。

## 5. 关键数据流

### 5.1 接入数据流
业务项目接入 Base → Collector 建立连接 → Visual 记录 Workspace / 项目接入状态 → 首页展示接入结果

### 5.2 运行态数据流
业务项目中运行需求 → 运行态产物写入本地 → Collector 上报 → Visual 聚合 → 首页显示运行态和阻塞态

### 5.3 资产检测数据流
Collector 扫描 rules / skills / openspec / `.ai-spec` / registry / logs → Visual 计算完整度 → 首页显示资产命中情况

### 5.4 结果数据流
需求归档 → Visual 汇总归档数据 → 首页生成闭环进度与效率收益视图

## 6. 非功能设计要求
- 首页支持模块级降级，不允许单接口故障拖垮整页
- Demo 模式和真实模式共用页面结构
- 接口层支持聚合与拆分两种实现策略
- 埋点和业务展示解耦
- 数据模型预留 Team 模式扩展字段

## 7. 扩展方向
- 更强控制能力
- 更细粒度权限
- 更完整审计日志
- 更丰富试点统计
- 跨团队、多 Workspace 统一治理
