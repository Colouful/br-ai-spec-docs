# 首页测试设计文档

## 1. 文档基本信息
- 文档名称：BR AI Spec Visual 首页测试设计文档
- 适用版本：首页首版 / Demo-first，Team-ready
- 测试对象：Dashboard 首页及其首版相关模块
- 目标环境：开发环境、测试环境、Demo Workspace 环境
- 关联页面：Dashboard 首页、Runs 列表页跳转、接入引导入口、Demo Workspace 入口

## 2. 测试目标
本次测试的目标不是只验证“页面能打开”，而是系统性验证以下能力：

1. 首页首屏是否可正常展示并传达核心价值  
2. 各模块是否支持独立加载、独立报错、独立空态处理  
3. Demo 模式和真实 Workspace 模式是否都能稳定运行  
4. 各聚合接口是否满足前端展示与状态切换需求  
5. 首页关键按钮与跳转链路是否完整  
6. 埋点是否按预期上报  
7. 页面在常见异常场景下是否具备可恢复能力  

## 3. 测试范围

### 3.1 包含范围
- Dashboard 首页整体布局与首屏展示
- TopNav 顶栏与 Workspace 切换
- DashboardHeader 标题区与快捷操作
- OnboardingCard
- RuntimeHealthCard
- DeliveryProgressCard
- EfficiencyValueCard
- BlockFlowPanel
- AssetCoveragePanel
- RecentRunsTable
- RecentChangesPanel
- InstallationTrendPanel
- PilotProjectsPanel
- PilotReviewPanel
- 首页关键跳转
- 首页关键埋点

### 3.2 不包含范围
- Runs 详情页深层业务逻辑
- Workspace 后台管理复杂权限编辑
- 非首页相关的多页面联动细节
- 非首版移动端专项适配
- 后续 Team 模式高级治理功能

## 4. 测试策略

### 4.1 测试层次
1. 模块级测试：验证单个模块的展示、状态切换与交互行为  
2. 页面级测试：验证首页整体布局、请求顺序与模块组合后的表现  
3. 接口联调测试：验证前后端字段、空态、异常态、错误码处理  
4. 埋点测试：验证关键行为事件是否准确上报  
5. 回归测试：验证模块变更后对首页整体的影响  

### 4.2 测试方法
- 手工功能测试
- 接口 Mock + 真接口联调测试
- 控制台 / 抓包验证埋点
- 异常模拟测试（接口 4xx/5xx、超时、字段缺失）
- Demo 数据与真实数据双模式测试

## 5. 测试维度

### 5.1 功能测试
验证页面、模块、按钮、筛选、跳转和卡片展示逻辑。

### 5.2 状态测试
重点覆盖：
- loading
- empty
- error
- retry
- partial success（部分模块成功、部分失败）

### 5.3 接口测试
验证：
- 参数正确性
- 字段映射
- 空数组处理
- 错误码处理
- 字段缺失容错

### 5.4 权限测试
验证：
- Workspace 不存在
- Workspace 无访问权限
- Workspace 已创建但未接入
- Workspace 已接入但数据未准备完成

### 5.5 数据模式测试
验证：
- Demo Workspace 模式
- 真实 Workspace 模式
- 两种模式的字段、文案与页面状态一致性

### 5.6 埋点测试
验证关键页面与交互埋点是否上报完整、字段是否正确。

### 5.7 兼容性测试
建议至少覆盖：
- Chrome 最新版
- Edge 最新版
- Safari 最新版（macOS）

### 5.8 性能与体验测试
验证：
- 首屏模块优先渲染
- 次级模块延迟加载是否合理
- 单模块失败不影响其他模块渲染

## 6. 测试环境与数据准备

### 6.1 环境准备
- 开发环境：前端本地 + Mock 数据
- 测试环境：真实接口联调环境
- Demo 环境：带示例数据的 Demo Workspace

### 6.2 测试数据准备
至少准备以下数据集：

1. 未接入数据集  
   - Workspace 已存在  
   - Base 未安装  
   - 无 Collector 数据  

2. 已安装未联通数据集  
   - Base 已安装  
   - Visual 未联通  
   - 部分资产缺失  

3. 已联通未启动需求数据集  
   - 可显示已接入状态  
   - 无 Run 数据  

4. 有运行无归档数据集  
   - 有 Run  
   - 有阻塞或进行中状态  
   - 无归档结果  

5. 有归档数据集  
   - 至少 1 个已归档需求  
   - 可显示闭环率与效率收益  

6. 资产缺失数据集  
   - 缺失 registry / logs / openspec 中的任意项  
   - 支持验证资产修复提示  

7. 阻塞数据集  
   - 覆盖 before_implementation / before_guardian / before_archive 三类阻塞  

8. 接口异常数据集  
   - 4xx / 5xx / timeout / 字段缺失  

## 7. 模块测试重点

### 7.1 OnboardingCard
重点验证：
- 不同接入阶段展示
- 资产检测结果展示
- 下一步建议是否正确
- 缺失资产提示
- 快捷入口跳转

### 7.2 RuntimeHealthCard
重点验证：
- 运行中需求数、异常数展示
- 趋势图渲染
- lastSyncTime 展示逻辑
- 点击进入 Runs 页

### 7.3 DeliveryProgressCard
重点验证：
- 今日发起、今日归档、本周闭环率展示
- 数据为空时文案
- 数值边界情况（0、1、极大值）

### 7.4 EfficiencyValueCard
重点验证：
- 平均时长与节省时长范围展示
- estimationType 对应文案
- 数据未准备完成时展示逻辑

### 7.5 BlockFlowPanel
重点验证：
- 阻塞阶段分布
- 原因 Top N
- 最近 24 小时新增阻塞
- 阻塞预览项点击行为

### 7.6 AssetCoveragePanel
重点验证：
- 资产状态清单展示
- 缺失项高亮
- repairHint 展示
- 评分展示与边界值

### 7.7 RecentRunsTable
重点验证：
- 正常列表展示
- 空态展示
- 分页
- blocked 状态展示
- 操作跳转

## 8. 接口测试点
每个接口至少验证以下内容：

1. 正常返回  
2. 空返回  
3. 错误返回  
4. 字段缺失  
5. 非法参数  
6. Workspace 无权限  

重点接口特别要求：
- `/api/dashboard/summary`：首屏依赖高，需重点验证响应时延与字段完整性
- `/api/dashboard/onboarding`：需验证 stage 与 assetChecklist 是否逻辑一致
- `/api/dashboard/block-flow`：需验证 blockedStageStats 与 blockedReasonTop 是否能独立为空
- `/api/dashboard/asset-coverage`：需验证 coverageScore 与 missingItems 对应关系

## 9. 埋点测试设计
首版重点埋点事件：
- `dashboard_viewed`
- `onboarding_action_clicked`
- `module_card_clicked`
- `efficiency_snapshot_generated`
- `asset_detected`

验证项：
1. 是否触发  
2. 是否只触发一次或按预期次数触发  
3. 关键字段是否完整  
4. 枚举值是否符合规范  
5. 页面跳转后是否仍能保留必要上下文  

## 10. 验收标准
满足以下条件方可视为首页测试通过：

1. 首屏 P0 模块全部正常展示  
2. 模块级 loading / empty / error 状态全部覆盖  
3. 首页关键跳转行为正常  
4. 首页关键接口联调通过  
5. 首页关键埋点上报准确  
6. Demo 模式和真实模式均可运行  
7. 任意单模块报错不影响整页可用性
