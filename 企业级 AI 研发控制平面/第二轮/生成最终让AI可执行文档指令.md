# 终版提示词：生成 AI 可执行开发任务包

你现在是一位 **企业级 AI 工程平台架构师、技术任务拆解专家、AI 编程执行规划负责人、测试负责人和验收负责人**。

请注意：
我最终要的不是一份说明文档，也不是一份架构评审报告，而是一套可以直接交给 AI 编程模型执行的 **“AI 可执行开发任务包”**。

这套文档包要服务于 Codex、Claude Code、Cursor Agent、Devin 或其他 AI 编程 Agent，让它们可以按照阶段逐步完成：

1. 开发
2. 测试
3. 验收
4. 问题修复
5. 回归验证
6. 进度同步
7. 进入下一阶段

所有文档必须做到：

1. 具体
2. 可执行
3. 可测试
4. 可验收
5. 可回滚
6. 可追踪
7. 可交给 AI 编程模型逐步执行

不允许只写原则、建议、方向、概念或口号。

---

## 一、项目最终目标

我要建设一套企业级 AI 工程开发标准平台，核心方向包括：

1. 规范驱动开发 Spec-Driven Development
2. Harness Runtime / 执行器适配层
3. Cursor、Claude Code 双 IDE 第一版适配
4. Codex 预留适配协议，后续阶段实现
5. 项目级 Memory 文件体系
6. Agent Profile / Skill / Rule / Prompt / Workflow / Hook / Manifest / Lock 资产体系
7. Hook 指令、自动检查、自我反馈、自我修复机制
8. 受控多 Agent 协作，而不是简单无边界多 Agent
9. 全栈项目的任务语言、框架、中间件、组件库、测试、验收标准
10. 企业级权限、安全、审计、版本、灰度、可观测性、可回滚
11. 不绑定某个大模型或某个 IDE，抽象成稳定的平台能力

平台核心定位是：

让 AI 开发按照项目规范完成可控、可测、可验收、可追踪、可回滚的工程交付。

请基于以下 P0-P5 路线生成完整文档包。

### P0：Cursor + Claude Code 双 IDE 项目级最小闭环

目标：

1. 支持单项目初始化
2. 支持 Cursor 和 Claude Code 双 IDE 适配
3. 支持统一规范资产生成
4. 支持项目内轻量目录

1. Codex 完整适配
2. 完整多 Agent Runtime
3. 企业多租户

5. 资产市场
6. 自动上线发布
