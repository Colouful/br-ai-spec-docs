# I4-文档同步与最终验收-测试文档

## 1. 测试目标

验证 `br-ai-spec-docs` 中 `文档同步与最终验收` 的实现满足技术实现文档要求，并确保不会破坏现有功能。

## 2. 测试范围

1. 本阶段新增或修改的模块。
2. 本阶段涉及的 Schema / API / 文件输出。
3. 与其他仓库联调所需的 Fixture 或 Mock。
4. 本阶段回滚路径。

## 3. 不测试范围

1. 不测试其他仓库内部实现。
2. 不测试未进入本阶段范围的长期能力。
3. 不测试真实线上数据。
4. 不测试模型真实调用效果，除非项目已有稳定测试环境。

## 4. 测试前置条件

1. 当前目录必须是 `br-ai-spec-docs` 仓库。
2. 已安装项目依赖。
3. 已创建本阶段测试分支。
4. 已准备本阶段需要的 Fixture。
5. 若需要环境变量，必须使用测试环境值，不得使用生产密钥。

## 5. 测试类型

单元测试、集成测试、回归测试、异常测试、兼容性测试、安全测试、回滚测试。

## 6. 测试用例表

| 用例编号 | 测试类型 | 测试场景 | 前置条件 | 操作步骤 | 预期结果 | 优先级 |
| --- | --- | --- | --- | --- | --- | --- |
| I4.TC1 | 成功路径 | 按技术实现文档执行本阶段核心流程 | 当前仓库已安装依赖 | 执行本阶段主流程 | 流程成功，输出结构符合要求 | P0 |
| I4.TC2 | 异常测试 | 构造缺字段、依赖失败或非法输入 | 准备异常 Fixture | 执行本阶段主流程 | 返回明确错误，不静默失败 | P0 |
| I4.TC3 | 安全测试 | 输入包含密钥、原始 Prompt、源码摘要 | 准备敏感样例 | 执行脱敏或接口校验 | 敏感信息被拒绝或脱敏 | P0 |
| I4.TC4 | 回归测试 | 执行项目已有核心测试 | 依赖已安装 | 执行测试命令 | 原有功能不被破坏 | P0 |
| I4.TC5 | 回滚测试 | 按技术文档回滚方案恢复 | 存在本阶段变更 | 执行回滚和验证命令 | 可恢复到执行前状态 | P1 |

## 7. 自动化测试建议

1. Schema 校验测试应自动化。
2. API 成功与失败路径应自动化。
3. CLI 命令输出与文件生成应自动化。
4. 前端页面应至少覆盖渲染、空数据、异常数据。
5. 资产安装、上报、回滚等跨仓库逻辑应使用 Fixture 测试。
6. Mock 策略：外部服务使用本包提供的样例 JSON，不允许依赖线上服务。
7. 边界场景：缺字段、版本不兼容、空数组、重复数据、权限不足、网络失败。
8. 异常场景：上报失败、安装失败、校验失败、回滚失败。

## 8. 命令行测试指令

执行模型必须根据实际项目技术栈修正命令，并将真实结果写入验收结果文档。

- `文档检查：确认链接、目录、术语一致`

通用兜底命令：`npm run lint`、`npm test`、`npm run build`、`pnpm lint`、`pnpm test`、`pnpm build`。

## 9. 失败排查指南

先看命令输出，再看本阶段变更文件，再看配置文件，再看日志，再看依赖版本，再看 Schema 兼容性，再检查是否修改无关模块。不允许删除测试绕过失败。

## 10. 测试通过标准

1. 本阶段新增测试通过。
2. 项目原有核心测试不下降。
3. 构建命令通过。
4. 安全与脱敏用例通过。
5. 回滚测试路径可执行。
6. 真实结果已记录到验收结果文档。
