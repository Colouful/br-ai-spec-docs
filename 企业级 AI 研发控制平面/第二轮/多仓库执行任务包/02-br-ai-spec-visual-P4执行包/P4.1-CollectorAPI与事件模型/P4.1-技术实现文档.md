# P4.1-CollectorAPI与事件模型-技术实现文档

## 1. 阶段目标

在 br-ai-spec-visual 中实现接收 br-ai-spec Run Event / Evidence 的最小 Collector API 和数据模型。

## 2. 目标仓库

`br-ai-spec-visual`

## 3. 本阶段范围

新增或复用 Collector API、Run/Event/Evidence 数据存储、Schema 校验和脱敏校验。

## 4. 不在本阶段范围内的内容

不实现 br-ai-spec CLI；不实现 Hub 资产管理。

## 5. 前置条件

1. 已阅读根目录 `README.md`。
2. 已阅读 `00-多仓库职责边界说明.md`。
3. 已确认当前仓库为 `br-ai-spec-visual`。
4. 已创建本阶段独立开发分支。
5. 如依赖其他仓库输出，必须使用本包提供的 Schema / Fixture，不允许自行臆造协议。

## 6. 相关模块与文件

建议文件定位：API 路由、services/collector、models/run、models/event、pages 或 app 目录，实际位置【待确认】。

如果无法确定具体文件，请基于项目结构定位并在进度同步文档中标记【待确认】。

## 7. 当前问题

1. `br-ai-spec` 已经执行过 P0-P5，但 Visual 和 Hub 仓库尚未完成对应主体能力。
2. P4 / P5 不能继续在单仓库中闭门实现。
3. 后续必须先完成边界收口，再补连接器、Visual 观测、Hub 资产中心和四仓联调。

## 8. 目标设计

1. 当前阶段职责只落在指定仓库。
2. 与其他仓库通过明确 Schema / API / Fixture 对接。
3. 变更可测试、可验收、可回滚。
4. 不污染业务项目，不存储敏感数据。
5. 所有真实测试和验收结果必须由执行模型在执行后填写。

## 9. 技术实现方案

### 9.1 模块设计

围绕 `CollectorAPI与事件模型` 建立最小可用实现，优先复用现有模块；不存在时再新增最小实现。

### 9.2 接口设计

涉及跨仓库时优先使用本包 `05-跨仓库协议与样例数据/` 下的 Schema。接口必须保持稳定、向后兼容。

### 9.3 数据结构

所有结构化数据必须包含版本字段、时间字段、来源字段和兼容策略。严禁无版本裸结构跨仓库传输。

### 9.4 配置结构

配置必须支持默认值。敏感配置必须来自环境变量或用户本地配置，不允许写入 Git。

### 9.5 文件结构

新增文件必须放在本阶段允许范围内；如果现有项目已有同类目录，必须复用。

### 9.6 调用流程

读取配置 → 校验输入 → 执行业务逻辑 → 输出结构化结果 → 写日志 / 事件 → 返回结果。

### 9.7 异常处理

必须区分参数错误、权限错误、依赖不可用、数据不兼容、执行失败和未知错误。

### 9.8 兼容策略

新增字段必须可选；删除字段必须保留兼容读取；接口变更必须支持旧版本最小读取。

### 9.9 回滚策略

所有新增文件可通过 Git 回滚；数据库变更必须有迁移回滚说明；配置变更必须能恢复默认值。

### 9.10 日志要求

日志必须记录阶段编号、仓库、操作、结果、错误摘要，不记录密钥、原始 Prompt、完整源码。

### 9.11 权限要求

涉及写操作、发布、回滚、审计、上报时必须进行权限或配置校验。

### 9.12 安全要求

必须脱敏敏感字段；不得上传源码；不得存储原始 Prompt；不得绕过 Hook / Policy / Test。

### 9.13 测试影响范围

测试必须覆盖本阶段新增或修改的核心流程，至少包含成功路径、失败路径和回滚路径。


## 字段与 JSON 结构要求

### RunEvent

| 字段名 | 字段类型 | 是否必填 | 默认值 | 字段说明 | 示例值 | 校验规则 | 兼容策略 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| eventId | string | 是 | 无 | 事件唯一 ID | evt_001 | 非空 | 新增字段必须可选 |
| runId | string | 是 | 无 | 运行任务 ID | run_20260507_001 | 非空 | 跨版本保持稳定 |
| projectId | string | 是 | 无 | 项目 ID | br-ai-spec-a83f91c2 | 非空 | 与 Local State 一致 |
| eventType | string | 是 | 无 | 事件类型 | hook.finished | 枚举 | 新增枚举向后兼容 |
| stage | string | 是 | 无 | 阶段 | post-test | 非空 | 未知阶段允许展示为其他 |
| status | string | 是 | unknown | 状态 | success | success/failure/running/skipped/unknown | 新增状态默认 unknown |
| severity | string | 否 | info | 严重程度 | blocking | info/warn/error/blocking | 默认 info |
| message | string | 否 | 空字符串 | 事件摘要 | 测试通过 | 长度限制 | 敏感信息脱敏 |
| timestamp | string | 是 | 当前时间 | ISO 时间 | 2026-05-07T00:00:00Z | ISO8601 | 保持 UTC |
| metadata | object | 否 | {} | 扩展信息 | {} | 必须可 JSON 序列化 | 不可放源码/密钥/原始 Prompt |

JSON 示例：

```json
{
  "eventId": "evt_001",
  "runId": "run_20260507_001",
  "projectId": "br-ai-spec-a83f91c2",
  "eventType": "hook.finished",
  "stage": "post-test",
  "status": "success",
  "severity": "info",
  "message": "post-test 检查通过",
  "timestamp": "2026-05-07T00:00:00Z",
  "metadata": {
    "hookId": "post-test",
    "durationMs": 1200
  }
}
```
