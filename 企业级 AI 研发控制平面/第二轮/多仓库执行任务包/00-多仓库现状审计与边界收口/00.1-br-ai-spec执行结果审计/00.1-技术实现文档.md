# 00.1-br-ai-spec执行结果审计-技术实现文档

## 1. 阶段目标

检查当前 `br-ai-spec` 已执行 P0-P5 后的真实完成情况，识别应保留、应迁移、应删除或应补充的内容。

## 2. 目标仓库

`br-ai-spec`

## 3. 本阶段范围

只做审计与报告，不修改代码。

## 4. 不在本阶段范围内的内容

不做功能开发；不修改 Visual / Hub；不删除现有代码。

## 5. 前置条件

1. 已阅读根目录 `README.md`。
2. 已阅读 `00-多仓库职责边界说明.md`。
3. 已确认当前仓库为 `br-ai-spec`。
4. 已创建本阶段独立开发分支。
5. 如依赖其他仓库输出，必须使用本包提供的 Schema / Fixture，不允许自行臆造协议。

## 6. 相关模块与文件

重点查看 CLI、Manifest、Lock、Adapter、Hook、Repair、Evidence、P4/P5 相关目录。若文件不确定，标记【待确认】。

如果无法确定具体文件，请基于项目结构定位并在进度同步文档中标记【待确认】。

## 7. 当前问题

1. `br-ai-spec` 已经执行过 P0-P5，但 Visual 和 Hub 仓库尚未完成对应主体能力。
2. P4 / P5 不能继续在单仓库中闭门实现。
3. 后续必须先完成边界收口，再补连接器、Visual 观测、Hub 资产中心和四仓联调。

## 8. 目标设计

1. 当前阶段职责只落在指定仓库。
2. 与其他仓库通过明确 Schema / API / Fixture 对接。
3. 变更可测试、可验收、可回滚。
4. 不污染业务项目，不存储敏感数据。
5. 所有真实测试和验收结果必须由执行模型在执行后填写。

## 9. 技术实现方案

### 9.1 模块设计

围绕 `br-ai-spec执行结果审计` 建立最小可用实现，优先复用现有模块；不存在时再新增最小实现。

### 9.2 接口设计

涉及跨仓库时优先使用本包 `05-跨仓库协议与样例数据/` 下的 Schema。接口必须保持稳定、向后兼容。

### 9.3 数据结构

所有结构化数据必须包含版本字段、时间字段、来源字段和兼容策略。严禁无版本裸结构跨仓库传输。

### 9.4 配置结构

配置必须支持默认值。敏感配置必须来自环境变量或用户本地配置，不允许写入 Git。

### 9.5 文件结构

新增文件必须放在本阶段允许范围内；如果现有项目已有同类目录，必须复用。

### 9.6 调用流程

读取配置 → 校验输入 → 执行业务逻辑 → 输出结构化结果 → 写日志 / 事件 → 返回结果。

### 9.7 异常处理

必须区分参数错误、权限错误、依赖不可用、数据不兼容、执行失败和未知错误。

### 9.8 兼容策略

新增字段必须可选；删除字段必须保留兼容读取；接口变更必须支持旧版本最小读取。

### 9.9 回滚策略

所有新增文件可通过 Git 回滚；数据库变更必须有迁移回滚说明；配置变更必须能恢复默认值。

### 9.10 日志要求

日志必须记录阶段编号、仓库、操作、结果、错误摘要，不记录密钥、原始 Prompt、完整源码。

### 9.11 权限要求

涉及写操作、发布、回滚、审计、上报时必须进行权限或配置校验。

### 9.12 安全要求

必须脱敏敏感字段；不得上传源码；不得存储原始 Prompt；不得绕过 Hook / Policy / Test。

### 9.13 测试影响范围

测试必须覆盖本阶段新增或修改的核心流程，至少包含成功路径、失败路径和回滚路径。

## 12. AI 编程模型执行提示词

你现在执行【00.1：br-ai-spec执行结果审计】。

请先阅读以下文档：

1. 本技术实现文档
2. 本阶段测试文档
3. 本阶段验收结果文档
4. 本阶段进度同步文档
5. `00-多仓库职责边界说明.md`
6. `05-跨仓库协议与样例数据/` 中与本阶段相关的 Schema

你的任务是：

1. 理解本阶段目标和边界。
2. 只修改 `br-ai-spec` 仓库中本阶段允许修改的文件和模块。
3. 按照技术实现文档完成开发。
4. 按照测试文档执行测试。
5. 将真实测试结果写入验收结果文档。
6. 更新进度同步文档。
7. 判断是否满足进入下一阶段的条件。

测试命令参考：

- `pnpm lint`
- `pnpm test`
- `pnpm build`

严格禁止扩大范围、跳过测试、删除测试、伪造结果、修改无关模块、引入未说明的大型依赖、破坏向后兼容、把运行态数据写入项目仓库、提交密钥/原始 Prompt/敏感日志。

完成后请输出：修改文件清单、实现摘要、执行的测试命令、测试结果、验收结果、进度同步结果、遗留问题、是否建议进入下一阶段。


## 禁止事项

1. 不允许把 Visual UI、Asset Hub 后台、企业管理页面继续塞进 `br-ai-spec`。
2. 不允许在 `br-ai-spec-visual` 中实现 CLI、Harness 执行器或资产安装逻辑。
3. 不允许在 `skill-q-platform` 中存储业务源码、原始 Prompt、密钥、敏感日志。
4. 不允许跳过测试、删除测试、降低测试标准或伪造测试结果。
5. 不允许静默忽略失败，所有失败必须记录到验收结果文档和进度同步文档。
6. 不允许破坏现有接口兼容性；如必须变更，必须提供兼容层和迁移说明。
7. 不允许引入未说明的大型依赖。
8. 不允许把运行态数据写入业务项目仓库。
9. 不允许跨仓库随意修改；每个小阶段只能修改当前文档允许的仓库与文件。
10. 不允许提交密钥、原始 Prompt、敏感日志、完整源码快照。


## 14. 风险与回滚方案

| 风险 | 触发条件 | 影响范围 | 回滚方式 | 回滚验证命令 |
