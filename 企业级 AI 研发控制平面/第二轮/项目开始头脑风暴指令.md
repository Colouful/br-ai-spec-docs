# 一、核心目标

我要从 0 重新设计一套企业级 AI 工程开发标准平台，核心方向是：

1. 规范驱动开发 Spec-Driven Development
2. Harness / Agent Runtime / 执行器适配层
3. Cursor、Claude Code、Codex IDE 等多执行器适配
4. 项目级 Memory 文件体系
5. Agent Profile / Skill / Rule / Prompt / Workflow 等资产体系
6. Hook 指令、自动检查、自我反馈、自我修复机制
7. 多 Agent 协作，而不是简单状态机编排
8. 全栈项目的任务语言、框架、中间件、组件库、测试、验收标准
9. 企业级架构、权限、安全、审计、版本、灰度、可观测性、可回滚
10. 不因大模型能力升级而快速过时，必须抽象成稳定的平台能力，而不是绑定某个模型或 IDE

你要帮我判断：

- 这个项目到底应该解决什么最核心的问题？
- 之前“状态机 + 编排”的思路哪里不够好？
- 多 Agent 是否真的优于状态机？还是应该是“规范主线 + Agent 协作 + Harness 门禁”的混合架构？
- 如何设计成企业级、可维护、可扩展、可治理的平台？
- 如何让 Cursor、Claude Code、Codex IDE 都能稳定使用这套规范？
- 如何设计 Memory、Hook、Agent、Skill、Rule、Spec、Test、Review、Feedback、Repair 的闭环？
- 如何让全栈项目从需求、设计、编码、测试、验收、上线、复盘都能被 AI 高质量辅助？
- 如何避免产品做成“功能很多但不清晰”的工具堆砌？
