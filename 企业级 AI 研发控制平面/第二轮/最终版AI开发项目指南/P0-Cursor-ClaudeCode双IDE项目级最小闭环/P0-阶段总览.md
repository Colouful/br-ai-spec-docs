# P0-阶段总览：Cursor + Claude Code 双 IDE 项目级最小闭环

## 1. 阶段目标

让单个项目在 Cursor 与 Claude Code 中基于同一套规范资产完成一次可检查、可修复、可归档的 AI 开发任务闭环。

## 2. 阶段边界

仅覆盖本地 CLI、项目轻量目录、用户本机运行态目录、Cursor Adapter、Claude Code Adapter、Spec/TestPlan/DoD、Hook/Test/Repair/Evidence 最小闭环。

## 3. 不在本阶段范围内的内容

| 禁止范围 |
| ---- |
| Codex 完整适配 |
| 完整多 Agent Runtime |
| 企业多租户 |
| 复杂 Visual 平台 |
| 资产市场 |
| 自动上线发布 |


## 4. 小阶段拆分

| 小阶段编号 | 小阶段名称 | 小阶段目标 |
| ---- | ---- | ---- |
| P0.1 | 项目理解与基线确认 | 理解当前项目代码结构、启动方式、测试命令、构建命令、现有目录和配置，不做业务逻辑修改。 |
| P0.2 | 项目初始化与目录治理 | 实现 br-spec init，初始化项目内轻量目录与用户电脑 ~/.ai-spec-auto/ 本地运行态目录。 |
| P0.3 | 统一 Manifest 与 Lock 机制 | 设计并实现 .ai-spec/manifest.json 与 .ai-spec/ai-spec.lock，支持资产声明、版本锁定、防篡改 hash、适配文件重新生成。 |
| P0.4 | CursorAdapter适配 | 根据 Manifest 生成 .cursor/rules/*.mdc，并保证 Cursor 读取同一套规范资产与 Memory。 |
| P0.5 | ClaudeCodeAdapter适配 | 生成 CLAUDE.md、.claude/commands、.claude/agents、.claude/settings.json，支持 Hook 调用统一 br-spec check。 |
| P0.6 | Spec-TestPlan-DoD闭环 | 支持需求结构化，生成 Spec、Test Plan、DoD、Review Checklist，并归档到 .ai-spec/specs/。 |
| P0.7 | Hook-Test-Repair-Evidence闭环 | 实现 Hook 生命周期、测试执行、最多 2 次自动修复、Evidence Report 生成。 |
| P0.8 | P0集成回归与阶段验收 | 完整执行一次 P0 闭环，验证双 IDE 输出一致、目录轻量、本地运行态、Hook/Test/Repair/Evidence、失败可回滚。 |

## 8. 核心数据结构

| 结构 | 用途 |
| ---- | ---- |
| Manifest | 统一声明 Rule、Skill、Agent Profile、Command、Hook、Adapter、Memory、Spec |
| Lock | 锁定资产版本、checksum、生成文件和适配输出 |
| Local State | 描述用户本机运行态目录和项目映射 |
| Run Event | 描述运行事件、Hook 事件、测试事件、修复事件 |
| Evidence Report | 描述一次任务的最终证据链 |
| Hook Config | 描述 Hook 生命周期、命令、阻塞策略和输出位置 |
| Agent Profile | 描述 Agent 身份、职责、权限、上下文边界和升级策略 |

## 10. 测试策略

1. 每个小阶段先执行单元测试或配置校验。
2. 涉及 CLI 的阶段执行命令行集成测试。
3. 涉及目录和生成文件的阶段执行快照或文件存在性校验。
4. 涉及安全与权限的阶段执行异常与越权测试。
5. 集成回归阶段执行完整端到端验证。

## 11. 验收策略

每个小阶段验收结果文档默认均为模板状态。真实执行后才能填写通过或失败。阶段验收必须汇总小阶段验收结果。

## 12. 风险与回滚策略

| 风险 | 回滚策略 |
| ---- | ---- |
| 生成文件破坏现有项目 | 删除生成文件并恢复 Git 状态 |
| 配置格式错误 | 恢复上一版本配置和 lock |
| 运行态写入项目仓库 | 删除污染目录并修复 Local State 写入策略 |
| 测试失败 | 进入待修复状态，修复后重新测试 |
| 无法判断 | 标记阻塞并记录待确认信息 |


## 13. 阶段完成标准

1. 本阶段所有小阶段验收通过。
2. 必要测试真实执行并记录。
3. 无阻塞问题。
4. 回滚策略可执行或已记录待确认。
5. 阶段进度同步文档已更新。
