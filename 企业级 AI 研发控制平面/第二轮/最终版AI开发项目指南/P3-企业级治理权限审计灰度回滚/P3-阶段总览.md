# P3-阶段总览：企业级治理、权限、审计、灰度、回滚

## 1. 阶段目标

把工具升级为企业可管理、可审计、可灰度、可回滚的平台能力。

## 2. 阶段边界

覆盖 RBAC、资产审核流、审计日志、灰度发布、版本回滚、安全策略、P3 集成验收。

## 3. 不在本阶段范围内的内容

| 禁止范围 |
| ---- |
| 训练私有大模型 |
| 替代 Git/CI/CD |
| 替代企业 IAM |
| 完全自动审批 |


## 4. 小阶段拆分

| 小阶段编号 | 小阶段名称 | 小阶段目标 |
| ---- | ---- | ---- |
| P3.1 | RBAC权限模型 | 实现组织、团队、项目、用户、角色、权限点的最小 RBAC 数据模型和校验。 |
| P3.2 | AssetReviewWorkflow | 实现资产草稿、提交审核、审核通过、发布、拒绝、废弃的状态流转。 |
| P3.3 | 审计日志 | 记录关键操作，包括资产变更、权限变更、策略拒绝、灰度发布、回滚执行。 |
| P3.4 | 灰度发布 | 支持按组织、团队、项目、比例发布资产版本，并记录灰度结果。 |
| P3.5 | 版本回滚 | 支持资产版本回滚、项目 lock 回滚、适配文件重新生成和回滚验证。 |
| P3.6 | SecurityPolicyEngine | 实现密钥保护、源码不出域、敏感信息脱敏、命令白名单、Prompt Injection Guard。 |
| P3.7 | P3集成回归与阶段验收 | 验证权限、审核、审计、灰度、回滚、安全策略是否闭环。 |

## 8. 核心数据结构

| 结构 | 用途 |
| ---- | ---- |
| Manifest | 统一声明 Rule、Skill、Agent Profile、Command、Hook、Adapter、Memory、Spec |
| Lock | 锁定资产版本、checksum、生成文件和适配输出 |
| Local State | 描述用户本机运行态目录和项目映射 |
| Run Event | 描述运行事件、Hook 事件、测试事件、修复事件 |
| Evidence Report | 描述一次任务的最终证据链 |
| Hook Config | 描述 Hook 生命周期、命令、阻塞策略和输出位置 |
| Agent Profile | 描述 Agent 身份、职责、权限、上下文边界和升级策略 |

## 10. 测试策略

1. 每个小阶段先执行单元测试或配置校验。
2. 涉及 CLI 的阶段执行命令行集成测试。
3. 涉及目录和生成文件的阶段执行快照或文件存在性校验。
4. 涉及安全与权限的阶段执行异常与越权测试。
5. 集成回归阶段执行完整端到端验证。

## 11. 验收策略

每个小阶段验收结果文档默认均为模板状态。真实执行后才能填写通过或失败。阶段验收必须汇总小阶段验收结果。

## 12. 风险与回滚策略

| 风险 | 回滚策略 |
| ---- | ---- |
| 生成文件破坏现有项目 | 删除生成文件并恢复 Git 状态 |
| 配置格式错误 | 恢复上一版本配置和 lock |
| 运行态写入项目仓库 | 删除污染目录并修复 Local State 写入策略 |
| 测试失败 | 进入待修复状态，修复后重新测试 |
| 无法判断 | 标记阻塞并记录待确认信息 |


## 13. 阶段完成标准

1. 本阶段所有小阶段验收通过。
2. 必要测试真实执行并记录。
3. 无阻塞问题。
4. 回滚策略可执行或已记录待确认。
5. 阶段进度同步文档已更新。
