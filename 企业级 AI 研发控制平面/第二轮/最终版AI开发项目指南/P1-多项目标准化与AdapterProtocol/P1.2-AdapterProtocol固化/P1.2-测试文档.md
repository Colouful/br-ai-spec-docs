# P1.2-测试文档：AdapterProtocol固化

## 1. 测试目标

验证本阶段“抽象 IDEAdapter 接口，统一 detect、generate、validate、diff、rollback 能力，保留 Codex adapter 协议入口。”是否真实可用、可回归、可回滚，并确保没有越界修改和运行态污染。

## 4. 测试前置条件

1. 当前代码分支已创建。
2. 上一阶段验收通过或已明确允许进入本阶段。
3. 依赖已安装。
4. 项目测试命令已确认；无法确认时标记【待确认】。
5. 工作区变更已记录，便于回滚。

## 5. 测试类型

| 测试类型 | 是否适用 | 说明 |
| ---- | ---- | ---- |
| 单元测试 | 适用 | 验证函数、Schema、工具方法 |
| 集成测试 | 适用 | 验证模块之间的调用和生成文件 |

| 兼容性测试 | 适用 | 多项目、多包管理器、已有配置 |
| 性能测试 | 按阶段适用 | 大项目扫描或大量事件聚合时执行 |

| AI 模型调用测试 | 不作为强依赖 | P0-P1 不要求真实模型调用 |
| 回滚测试 | 适用 | 验证回滚方案有效 |

## 7. 自动化测试建议

1. Schema 校验放在 `tests/schema/` 或现有测试目录【待确认】。
2. CLI 命令测试放在 `tests/cli/` 或 `__tests__/cli/`【待确认】。
3. 生成文件快照测试放在 `tests/fixtures/`。
4. Mock 策略：禁止真实写入用户 home，可通过临时目录模拟 `~/.ai-spec-auto/`。
5. 边界场景：目录已存在、配置已存在、字段缺失、checksum 不匹配、测试命令失败。
6. 异常场景：无写权限、路径包含空格、项目名称为空、Git 不存在。
7. 测试命名规则：`阶段编号-能力-场景`，例如 `P1.2-manifest-missing-field`。

## 9. 失败排查指南

1. 先看命令输出。
2. 再看变更文件。
3. 再看配置文件。
4. 再看日志。
5. 再看依赖版本。
6. 再看兼容性问题。
7. 不允许删除测试绕过失败。
8. 不允许降低测试标准。
9. 如果无法判断，记录【待确认】并标记阻塞。

## 10. 测试通过标准

1. 本阶段所有高优先级用例通过。
2. 必要命令执行结果为成功，或失败原因明确且不阻塞。
3. 未发现运行态数据进入项目 Git。
4. 未发现密钥、原始 Prompt、敏感日志进入 Git。
5. 回滚测试可执行或已明确记录【待确认】。
