# P1-阶段总览：多项目标准化与 Adapter Protocol

## 1. 阶段目标

让同一套规范资产可复制到多个项目，并固化 IDE Adapter Protocol、Asset Package 标准和配置分层。

## 2. 阶段边界

覆盖多项目 Scanner、Adapter Protocol、Asset Package、Config Layer、多项目接入验证与 P1 集成回归。

## 3. 不在本阶段范围内的内容

| 禁止范围 |
| ---- |
| 企业级权限审批 |
| 完整多 Agent Runtime |
| 复杂 Visual 大屏 |
| 资产市场运营 |


## 4. 小阶段拆分

| 小阶段编号 | 小阶段名称 | 小阶段目标 |
| ---- | ---- | ---- |
| P1.1 | 多项目Scanner增强 | 识别 React、Vue、Next.js、组件库、构建工具、包管理器、测试工具和 Monorepo 基础结构。 |
| P1.2 | AdapterProtocol固化 | 抽象 IDEAdapter 接口，统一 detect、generate、validate、diff、rollback 能力，保留 Codex adapter 协议入口。 |
| P1.3 | AssetPackage标准化 | 定义 asset-package 目录结构、manifest、校验、安装、升级、回滚规则。 |
| P1.4 | ConfigLayer配置分层 | 实现企业、团队、项目、本地用户配置的合并策略和覆盖优先级。 |
| P1.5 | 多项目接入验证 | 选择至少 3 类项目完成接入验证，记录差异和兼容问题。 |
| P1.6 | P1集成回归与阶段验收 | 验证多项目复制、Adapter 协议、资产包、配置分层、版本锁定与回滚。 |

## 8. 核心数据结构

| 结构 | 用途 |
| ---- | ---- |
| Manifest | 统一声明 Rule、Skill、Agent Profile、Command、Hook、Adapter、Memory、Spec |
| Lock | 锁定资产版本、checksum、生成文件和适配输出 |
| Local State | 描述用户本机运行态目录和项目映射 |
| Run Event | 描述运行事件、Hook 事件、测试事件、修复事件 |
| Evidence Report | 描述一次任务的最终证据链 |
| Hook Config | 描述 Hook 生命周期、命令、阻塞策略和输出位置 |
| Agent Profile | 描述 Agent 身份、职责、权限、上下文边界和升级策略 |

## 10. 测试策略

1. 每个小阶段先执行单元测试或配置校验。
2. 涉及 CLI 的阶段执行命令行集成测试。
3. 涉及目录和生成文件的阶段执行快照或文件存在性校验。
4. 涉及安全与权限的阶段执行异常与越权测试。
5. 集成回归阶段执行完整端到端验证。

## 11. 验收策略

每个小阶段验收结果文档默认均为模板状态。真实执行后才能填写通过或失败。阶段验收必须汇总小阶段验收结果。

## 12. 风险与回滚策略

| 风险 | 回滚策略 |
| ---- | ---- |
| 生成文件破坏现有项目 | 删除生成文件并恢复 Git 状态 |
| 配置格式错误 | 恢复上一版本配置和 lock |
| 运行态写入项目仓库 | 删除污染目录并修复 Local State 写入策略 |
| 测试失败 | 进入待修复状态，修复后重新测试 |
| 无法判断 | 标记阻塞并记录待确认信息 |


## 13. 阶段完成标准

1. 本阶段所有小阶段验收通过。
2. 必要测试真实执行并记录。
3. 无阻塞问题。
4. 回滚策略可执行或已记录待确认。
5. 阶段进度同步文档已更新。
