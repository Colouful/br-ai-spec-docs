# project-execution-docs

## 1. 文档包用途

本目录是一套面向 AI 编程模型的可执行开发任务包，用于指导 Codex、Claude Code、Cursor Agent、Devin 或其他 AI 编程 Agent 按 P0-P5 阶段完成企业级 AI 工程开发标准平台的开发、测试、验收、修复、回归、同步与阶段推进。

本任务包不是架构说明文档，而是执行约束文档。执行模型必须逐阶段读取对应技术实现文档、测试文档、验收结果文档和进度同步文档，按边界完成开发。

## 2. 适用对象

- AI 编程执行模型
- 技术负责人
- 测试负责人
- 架构评审负责人
- 企业 AI 工程平台建设团队
- 使用 Cursor、Claude Code、Codex、Devin 等工具的开发团队

## 3. 如何交给 AI 编程模型使用

推荐每次只交付一个小阶段目录，例如 `P0.2-项目初始化与目录治理/`。执行模型必须先阅读：

1. `00-总览/00-AI执行总指令.md`
2. 当前阶段总览文档
3. 当前小阶段技术实现文档
4. 当前小阶段测试文档
5. 当前小阶段验收结果文档
6. 当前小阶段进度同步文档

执行完成后，必须写入真实测试结果和进度记录。未经当前阶段验收确认，不允许进入下一阶段。

## 4. 推荐执行顺序

| 阶段 | 阶段名称 | 推荐顺序 |
| ---- | ---- | ---- |
| P0 | Cursor + Claude Code 双 IDE 项目级最小闭环 | 1 |
| P1 | 多项目标准化与 Adapter Protocol | 2 |
| P2 | 受控多 Agent 协作 | 3 |
| P3 | 企业级治理、权限、审计、灰度、回滚 | 4 |
| P4 | Visual 可观测、质量度量、运行复盘 | 5 |
| P5 | Asset Hub、组织级资产复用 | 6 |


## 5. P0-P5 阶段目标

| 阶段 | 目标 |
| ---- | ---- |
| P0 | 让单个项目在 Cursor 与 Claude Code 中基于同一套规范资产完成一次可检查、可修复、可归档的 AI 开发任务闭环。 |
| P1 | 让同一套规范资产可复制到多个项目，并固化 IDE Adapter Protocol、Asset Package 标准和配置分层。 |
| P2 | 引入专业 Agent 分工，但由 Harness 控制权限、上下文、文件范围、修复次数和人工门禁。 |
| P3 | 把工具升级为企业可管理、可审计、可灰度、可回滚的平台能力。 |
| P4 | 让每次 AI 开发任务可视化、可度量、可复盘、可优化。 |
| P5 | 建立企业级 Rule、Skill、Agent Profile、Workflow、Hook、Command 资产中心，支持搜索、安装、升级、回滚、继承、Fork、评分和反馈闭环。 |


## 6. 每个阶段输入和输出

| 阶段 | 输入 | 输出 |
| ---- | ---- | ---- |
| P0 | 现有项目代码、包管理器配置、测试命令、开发需求 | 项目内规范目录、用户本地运行态目录、Cursor/Claude 适配文件、Spec/TestPlan/DoD、Evidence Report |
| P1 | P0 稳定输出、多项目样本、资产包草案 | Scanner、Adapter Protocol、Asset Package、Config Layer、多项目验证报告 |
| P2 | P1 协议化能力、Agent Profile 草案 | 受控多 Agent 协作、权限边界、上下文边界、Review/Repair 闭环 |
| P3 | P2 Agent 协作能力、资产管理需求 | RBAC、审核、审计、灰度、回滚、安全策略 |
| P4 | P3 治理事件、运行事件、审计事件 | Run Timeline、Hook/Test/Repair/Agent 可视化、质量指标、风险看板 |
| P5 | P4 使用反馈、资产运行质量数据 | Asset Hub、资产搜索安装升级回滚、Fork/Override、质量评分 |


## 7. 每个阶段进入下一阶段的条件

1. 当前阶段所有小阶段状态为“已完成”。
2. 当前阶段测试文档中要求的测试命令真实执行并记录。
3. 当前阶段验收结果文档中关键验收项不为“待执行”或“失败”。
4. 当前阶段进度同步文档无阻塞项。
5. 阶段总览中的退出条件已满足。
6. 如存在非阻塞遗留问题，必须登记处理建议和后续阶段承接位置。

## 8. 如何记录测试结果

测试结果必须写入当前小阶段的“验收结果文档”和“进度同步文档”。不得伪造测试结果。未执行时必须填写“待执行”。

## 9. 如何记录验收结果

验收结果文档默认是模板状态。只有真实执行开发、测试和验收后，才能把“是否通过”从“待执行”改为真实结果。

## 10. 如何更新进度同步文档

每完成一个小任务，必须更新当前小阶段进度同步文档中的任务进度表、变更记录、测试执行记录和阻塞风险。必要时同步更新 `00-任务进度同步总表.md`。

## 11. 如何处理失败和回滚

失败时必须：

1. 记录失败命令和输出摘要。
2. 判断是代码错误、配置错误、测试错误、环境错误还是需求不明确。
3. 进入“待修复”状态。
4. 按文档允许范围修复。
5. 重新测试。
6. 无法修复时进入“已阻塞”或“已回滚”。
7. 回滚必须验证项目恢复到阶段开始前状态。

## 12. 禁止事项

- 不允许跳过阶段。
- 不允许擅自扩大范围。
- 不允许修改与当前阶段无关的模块。
- 不允许为了通过测试而删除测试或降低测试标准。
- 不允许伪造测试结果。
- 不允许伪造验收结果。
- 不允许静默忽略失败。
- 不允许绕过 Hook、权限、测试和验收要求。
- 不允许把运行态数据写入项目仓库。
- 不允许把密钥、原始 Prompt、敏感日志提交到 Git。
