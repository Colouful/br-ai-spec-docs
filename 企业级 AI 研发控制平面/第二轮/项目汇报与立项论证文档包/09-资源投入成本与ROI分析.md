# 资源投入、成本与 ROI 分析

## 1. 当前问题造成的隐性成本

| 隐性成本 | 表现 | 影响 |
|---|---|---|
| 重复 Prompt 成本 | 每个开发者重复描述规则 | 时间浪费、结果不一致 |
| Review 返工成本 | AI 产物质量不稳定 | 研发负责人和高级工程师被占用 |
| 缺陷后移成本 | 测试和验收不足 | 修复成本随阶段后移升高 |
| 新人上手成本 | 项目规范入口不清 | 熟悉项目周期变长 |
| 安全风险成本 | 密钥、源码、隐私边界不清 | 企业级风险 |
| 经验流失成本 | Prompt 和经验不资产化 | 人走经验走 |

## 2. 人力投入

| 角色 | 参与阶段 | 主要职责 | 投入强度 | 是否必须 |
| --- | --- | --- | --- | --- |
| 项目负责人 | P0-P5 | 目标对齐、范围控制、跨团队协调、验收 | 高 | 是 |
| 架构师 | P0-P5 | 总体架构、边界设计、技术评审 | 高 | 是 |
| 前端开发 | P0-P5 | CLI 可视化、Adapter、Visual 页面、文档站 | 中高 | 是 |
| 后端开发 | P1-P5 | Hub、治理、审计、事件、权限服务 | 中高 | P1 后必须 |
| 测试工程师 | P0-P5 | 测试策略、自动化测试、验收标准 | 中 | 是 |
| DevOps / 运维 | P3-P5 | 私有化部署、CI/CD、监控、备份 | 中 | 企业级必须 |
| 安全负责人 | P0-P5 | 密钥保护、脱敏、权限、合规策略 | 中 | 是 |
| 研发效能负责人 | P0-P5 | 指标体系、推广、流程集成 | 中 | 是 |
| 试点项目开发者 | P0-P2 | 真实场景试用、反馈、验证 | 中 | 是 |

## 3. 时间投入

| 阶段 | 目标 | 推荐周期 | 最小周期 | 风险缓冲 | 说明 |
| --- | --- | --- | --- | --- | --- |
| P0 | Cursor + Claude Code 双 IDE 项目级最小闭环 | 3-5 周 | 2 周 | 1 周 | 先验证真实闭环，不追求平台完整度 |
| P1 | 多项目标准化与 Adapter Protocol | 3-4 周 | 2 周 | 1 周 | 解决复制能力和资产包标准 |
| P2 | 受控多 Agent 协作 | 4-6 周 | 3 周 | 2 周 | 引入角色化协作，但严格受控 |
| P3 | 企业级治理、权限、审计、灰度、回滚 | 6-8 周 | 4 周 | 2 周 | 涉及权限、审计、流程、灰度 |
| P4 | Visual 可观测、质量度量、运行复盘 | 4-6 周 | 3 周 | 1-2 周 | 需要事件模型和指标口径稳定 |
| P5 | Asset Hub、组织级资产复用、资产市场 | 长期 | 6 周 | 持续 | 组织级资产运营，不建议一次性完成 |

## 4. 技术成本

| 技术成本 | 说明 | 影响阶段 | 投入强度 | 降低成本方式 |
| --- | --- | --- | --- | --- |
| CLI 开发成本 | 实现 init、check、repair、report 等命令 | P0-P1 | 中 | 先做最小命令集 |
| IDE Adapter 开发成本 | Cursor、Claude Code、Codex 适配 | P0-P2 | 中高 | P0 只做 Cursor + Claude Code |
| Hook Engine 开发成本 | 生命周期 Hook、阻塞策略、日志 | P0-P3 | 中 | 先固定 Hook 类型 |
| Memory Center 开发成本 | 分层 Memory、写入治理 | P0-P3 | 中 | 先文件化，再平台化 |
| Agent Runtime 开发成本 | Agent Profile、权限、上下文边界 | P2 | 高 | P0 不做完整 Runtime |
| Visual 平台开发成本 | Run Timeline、指标、看板 | P4 | 中高 | 先本地报告再上报 |
| Asset Hub 开发成本 | 资产搜索、安装、版本、审核 | P5 | 高 | 后置到资产稳定后 |
| 权限审计开发成本 | RBAC、Audit、Policy | P3 | 高 | 先本地 Evidence |
| 测试体系建设成本 | 测试模板、自动化、回归 | P0-P5 | 中 | 复用现有 CI |
| 私有化部署成本 | 容器、数据库、备份、监控 | P3-P5 | 高 | 按企业推广阶段投入 |

## 5. 维护成本

| 维护项 | 说明 | 降低方式 |
| --- | --- | --- |
| 规则维护 | 规则随框架和项目演进变化 | 设负责人和版本审核 |
| Skill 维护 | Skill 需要根据反馈优化 | 根据使用率和失败率排序维护 |
| Agent Profile 维护 | 角色权限和上下文要更新 | 固定核心 Agent，避免过多 |
| IDE 版本变化适配 | Cursor / Claude / Codex 能力变化快 | Adapter Protocol 隔离差异 |
| 模型能力变化适配 | 模型升级会改变最佳实践 | 保持平台抽象稳定 |
| 项目接入支持 | 不同项目差异大 | 模板化、扫描器、接入指南 |
| 文档维护 | 文档过期会影响使用 | 按版本维护文档 |
| 培训成本 | 开发者需理解新流程 | 10 分钟快速开始 + 示例项目 |
| 运行监控 | Visual 和事件需要维护 | P4 后统一指标平台 |
| 安全审计 | 策略和审计规则需更新 | 安全负责人参与审核 |

## 6. 推广成本

| 推广成本 | 表现 | 降低方式 |
|---|---|---|
| 开发者培训 | 需要理解 CLI、Spec、Hook、Memory | 快速开始、视频、模板 |
| 团队试点 | 需要真实项目验证 | 选择中等复杂度项目 |
| 规范迁移 | 老规范需要整理成资产 | 先迁移高频规则 |
| 项目接入 | 不同技术栈不同 | Scanner + 模板 |
| 使用习惯改变 | 开发者习惯直接问 AI | 用命令降低流程成本 |
| 推广阻力 | 觉得增加负担 | 用 P0 数据证明收益 |
| 组织协同 | 需要架构、测试、安全参与 | 明确角色和验收标准 |

## 7. 成本收益结论

| 投入类型 | 短期成本 | 长期成本 | 可降低方式 | 是否值得投入 |
| --- | --- | --- | --- | --- |
| 人力 | 中 | 中 | P0 小团队试点 | 值得 |
| 时间 | 中 | 可控 | P0 3-5 周见效 | 值得 |
| 技术 | 中高 | 中 | 协议化、分阶段 | 值得 |
| 维护 | 低中 | 中 | 资产评分和版本治理 | 值得 |
| 推广 | 中 | 中 | 试点数据和模板化 | 值得 |
| 治理 | 低 | 中高 | P3 再投入 | 阶段性值得 |

## 8. 三种投入版本

| 版本 | 范围 | 人力 | 周期 | 适用场景 |
|---|---|---|---|---|
| P0 最小投入版本 | 单项目、Cursor + Claude Code、本地闭环 | 3-5 人 | 3-5 周 | 验证可行性 |
| 团队试点投入版本 | 多项目、团队规则、Adapter Protocol | 5-8 人 | 2-3 月 | 团队推广 |
| 企业级推广投入版本 | 权限、审计、Visual、Hub、私有化 | 8-15 人 | 4-8 月 | 组织级落地 |
