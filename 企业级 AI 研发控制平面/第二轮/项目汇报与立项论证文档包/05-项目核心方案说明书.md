# 项目核心方案说明书

## 1. 项目定位

让 AI 开发按照项目规范完成可控、可测、可验收、可追踪、可回滚的工程交付。

它不是 Cursor、Claude Code、Codex 的替代品，而是它们之上的项目级规范底座、执行边界、资产体系、门禁体系和治理体系。

## 2. 设计原则

| 原则 | 说明 |
|---|---|
| 规范先行 | 先明确 Spec、Test Plan、DoD，再执行编码 |
| 执行受控 | AI 通过 Harness Runtime 进入工程世界 |
| 资产沉淀 | Rule、Skill、Agent、Workflow、Memory 都可版本化 |
| 低入侵 | P0 不污染业务项目，运行态进入 `~/.ai-spec-auto/` |
| 双 IDE 优先 | P0 先支持公司长期使用的 Cursor 和 Claude Code |
| 不绑定模型 | 平台协议稳定，执行器可替换 |
| 先闭环后平台 | 先验证 P0，再建设 P3/P4/P5 |
| 默认安全 | 密钥、原始 Prompt、敏感日志不提交 |

## 3. 核心理念

平台主线不是“多 Agent 自由协作”，也不是“状态机控制一切”，而是：规范主线 + Agent 协作 + Harness 门禁。

## 4. 四个闭环

| 闭环 | 内容 |
|---|---|
| 业务闭环 | 需求 → Spec → Test Plan → DoD → 交付 |
| 技术闭环 | Manifest → Adapter → Harness → Hook → Test → Evidence |
| 资产闭环 | Rule / Skill / Memory → 使用 → 反馈 → 版本升级 |
| 治理闭环 | 审核 → 灰度 → 发布 → 审计 → 回滚 |

## 5. 核心模块说明

| 模块 | 职责 | 不负责什么 |
| --- | --- | --- |
| Project Bootstrap CLI | 项目初始化、扫描、生成配置 | 不替代 IDE |
| Spec Center | 管理 Spec / Test Plan / DoD | 不直接改代码 |
| Harness Runtime | 控制执行边界、上下文、Hook、修复 | 不替代模型推理 |
| IDE Adapter | 生成 Cursor / Claude / Codex 配置 | 不绑定单工具 |
| Memory Center | 管理项目级和运行级 Memory | 不允许无限自动写长期记忆 |
| Hook Engine | 执行门禁和检查 | 不负责业务决策 |
| Agent Runtime | 专业 Agent 协作 | 不允许自由越权 |
| Test Engine | 运行测试和验证 | 不降低测试标准 |
| Feedback & Repair | 失败反馈和限次修复 | 不无限重试 |
| Security & Policy | 权限、安全、脱敏、策略 | 不依赖开发者自觉 |
| Local State Manager | 管理本地运行态 | 不把敏感态写入 Git |
| Visual Governance | 运行态可观测 | 不上传完整源码 |
| Asset Hub | 资产版本、审核、分发 | 不无审核发布 |

## 6. 与现有研发流程的关系

| 现有流程 | 平台关系 |
|---|---|
| Git | 不替代，只生成可审计资产和 Evidence |
| CI/CD | 不替代，调用并增强测试门禁 |
| Code Review | 不替代，提供 Review Checklist 和执行证据 |
| 测试体系 | 不替代，规范测试入口和结果归档 |
| 研发规范 | 不替代，把规范机器可读化和资产化 |
| IDE | 不替代，作为执行器适配 |

## 7. 为什么是“规范主线 + Agent 协作 + Harness 门禁”

| 方案 | 问题 | 正确定位 |
|---|---|---|
| 只靠多 Agent | 容易失控、成本高、冲突难处理 | Agent 做专业能力 |
| 只靠状态机 | 太僵硬，无法处理开放式工程判断 | 状态机做确定性控制 |
| 只靠 IDE | 不同工具规则割裂，企业治理不足 | IDE 是执行器 |
| 规范 + Agent + Harness | 兼顾确定性、智能和边界 | 平台主架构 |

## 8. 关键设计解释

1. 规范资产项目化：保证上下文不只存在聊天记录中。
2. 项目内目录和用户本机目录分离：项目内只放共享资产，运行态和敏感态进入 `~/.ai-spec-auto/`。
3. Manifest / Lock：保证资产版本可追踪、可回滚、防篡改。
4. P0 优先 Cursor + Claude Code：贴合公司长期工具使用习惯，最快验证真实价值。
5. Codex 后续预留：通过 Adapter Protocol 保留扩展点，避免 P0 范围失控。
6. 平台长期不会因模型升级而失去价值：规范、权限、测试、审计、资产治理是企业稳定需求。
