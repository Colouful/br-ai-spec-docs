# 竞品与参考方案对比分析

## 1. 分析结论摘要

本项目不应把 Cursor、Claude Code、Codex、Copilot、Devin 视为敌人。它们是优秀执行器和生态能力。本项目的差异化价值在于：跨 IDE 的项目级规范底座、Harness 门禁、资产版本治理、Memory 治理、Hook / Test / Review / Repair 闭环、Evidence / Audit 和企业级可观测。

## 2. 竞品概览

| 对象 | 它是什么 | 核心能力 | 适合场景 | 不解决什么 | 建议策略 |
| --- | --- | --- | --- | --- | --- |
| Cursor | AI IDE / Agent 编辑器 | 强代码编辑、项目 Rules、Agent | 个人与团队代码开发 | 不负责企业级跨 IDE 资产治理 | 集成 |
| Claude Code | 终端/IDE 中的 agentic coding tool | CLAUDE.md、commands、subagents、hooks | 复杂代码任务、代码库理解、团队命令 | 不是公司级 Asset Hub | 深度适配 |
| Codex | 云端软件工程 Agent | 沙盒执行、并行任务、AGENTS.md、测试证据 | 异步开发、PR、Bug 修复 | P0 不强依赖，后续适配 | 预留集成 |
| GitHub Copilot | GitHub 生态 AI 编程平台 | IDE 补全、agent mode、coding agent、skills | GitHub 工作流、企业协作 | 不提供跨工具规范底座 | 借鉴/集成 |

## 5. 差异化结论

| 维度 | 其他工具常见能力 | 本项目差异化 |
|---|---|---|
| 执行器 | 能写代码、运行命令、生成 PR | 不替代执行器，统一执行边界和规范入口 |
| 规范 | 有局部规则文件 | 将 Spec / Rule / Skill / Memory / Hook / Lock 资产化 |
| 多工具 | 每个工具单独配置 | 同一 Manifest 生成 Cursor / Claude / Codex 适配 |
| 验收 | 多依赖人工或工具内测试 | Hook / Test / Review / Repair / Evidence 闭环 |
| 治理 | 工具内有部分权限 | 企业级资产审核、灰度、审计、回滚 |
| 可观测 | 有日志或任务状态 | 统一 Run Event、指标、Visual 复盘 |
| 长期价值 | 跟随单工具能力变化 | 平台抽象稳定，不绑定单模型和单 IDE |

## 6. 哪些能力应该借鉴

1. 借鉴 Cursor 的 Project Rules 和 `.cursor/rules` 项目化规则机制。
2. 借鉴 Claude Code 的 `CLAUDE.md`、slash commands、subagents 和 hooks。
3. 借鉴 Codex 的 AGENTS.md、沙盒执行、终端日志和测试证据。
4. 借鉴 Copilot 的 GitHub 生态、coding agent、agent skills 和企业控制层。
5. 借鉴 Devin 的异步任务、嵌入式 IDE、PR Review 和任务接管能力。
6. 借鉴 OpenSpec 的 specs / changes / proposal / tasks 工作流。
7. 借鉴 gstack 的角色化命令和软件团队化工作流。
8. 借鉴 LangGraph 的状态、节点、边、checkpoint 思想。
9. 借鉴 Dify / Coze 的可视化 Workflow、工具配置和发布能力。

## 7. 哪些能力不适合照搬

1. 不照搬完整自治 Agent，因为企业研发需要边界和审计。
2. 不照搬单一 IDE 规则格式，因为会导致供应商绑定。
3. 不照搬复杂低代码 Agent 平台，因为本项目聚焦代码工程交付。
4. 不照搬大而全企业后台到 P0，因为会拖慢验证。
5. 不把状态图框架直接作为产品主线，因为状态机只是 Harness 的底层控制方式。

## 8. Build / Buy / Integrate 决策结论

| 能力 | 决策 | 原因 |
| --- | --- | --- |
| IDE 执行能力 | Integrate | Cursor / Claude / Codex 已经强，不自研 IDE |
| Spec 工作流 | Integrate + Build | 借鉴 OpenSpec，但补企业治理和双 IDE 适配 |
| Hook / 门禁 | Build | 需要统一项目级边界和企业策略 |
| Memory 治理 | Build | 需要企业可控、可审计、可回滚 |
| 多 Agent 执行 | Build + Integrate | 借鉴现有 subagents，但需要受控协作协议 |
| Visual 可观测 | Build | 需要统一 Run Event 和管理指标 |
| Asset Hub | Build | 公司级资产治理需要自有事实源 |
