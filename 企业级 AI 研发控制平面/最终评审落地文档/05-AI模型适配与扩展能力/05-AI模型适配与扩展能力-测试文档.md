# 05 AI模型适配与扩展能力 - 测试文档

## 1. 测试目标

验证阶段 05：【AI模型适配与扩展能力】的开发内容是否满足技术实现文档定义的目标、边界和验收标准。

## 2. 测试范围

- 定义 ModelProvider 接口
- 实现至少一个 MockModelProvider
- 实现 Prompt Template 版本和 checksum
- 实现模型调用成本记录
- 实现输出 JSON Schema 校验
- 实现失败 fallback 到人工或 mock
- 预留多模型配置

## 3. 不测试范围

- 不做完整 Model Gateway
- 不做复杂路由策略
- 不做 Prompt A/B 测试
- 不做模型评测平台
- 不接企业模型网关 UI

## 4. 测试前置条件

1. 当前阶段开发已完成。
2. 前置阶段验收已通过。
3. 当前 Git 工作区状态已记录。
4. 已安装项目依赖。
5. 已确认包管理器和测试命令。
6. 如命令不适配当前项目，必须根据阶段 00 基线结果修正并记录。

## 5. 测试类型

本阶段根据实际改动覆盖以下测试类型：

- 单元测试
- 集成测试
- 回归测试
- 异常测试
- 安全测试
- 兼容性测试
- 可观测性测试
- 回滚测试

## 6. 测试用例表

| 用例编号 | 测试类型 | 测试场景 | 前置条件 | 操作步骤 | 预期结果 | 优先级 |
|---|---|---|---|---|---|---|
| 05-C01 | 单元测试 | Mock provider 调用 | MockModelProvider 存在 | 调用 invoke | 返回符合 Schema 的响应 | P0 |
| 05-C02 | 单元测试 | Prompt checksum | Prompt 模板存在 | 读取模板并计算 checksum | run.bundle 记录版本和 checksum | P0 |
| 05-C03 | 异常测试 | 模型输出非法 JSON | 构造非法输出 | 调用 response-validator | 校验失败并重试一次 | P0 |
| 05-C04 | 可观测性测试 | 成本记录 | 执行一次模型调用 | 查看 metrics.json | 包含 provider、model、耗时、失败原因 | P0 |
| 05-C05 | fallback 测试 | 模型调用失败 | Mock 失败模式 | 执行 plan | 提示转人工或 fallback，不生成伪结果 | P1 |

## 7. 自动化测试建议

| 测试对象 | 建议位置 | 说明 |
|---|---|---|
| 新增模块单元测试 | `tests/` 或 `src/**/*.test.ts`【待确认】 | 根据当前项目测试框架确定 |
| CLI 集成测试 | `tests/cli/`【待确认】 | 使用临时目录模拟 Git 项目 |
| 文件系统测试 | `tests/fixtures/`【待确认】 | 使用 fixture 避免污染真实项目 |
| Guard 测试 | `tests/guards/`【待确认】 | 构造危险 diff 和敏感文件 |
| 回归测试 | 现有测试目录 | 确保旧功能不破坏 |

## 9. 失败排查指南

| 失败类型 | 排查步骤 |
|---|---|
| 类型检查失败 | 查看新增类型、导出路径、tsconfig include/exclude |
| 单元测试失败 | 先确认是否为本阶段改动导致，不允许删除测试 |
| CLI 命令失败 | 查看参数解析、运行目录、配置文件路径 |
| 文件系统测试失败 | 检查临时目录、权限、路径兼容性 |
| Git 相关失败 | 检查当前是否为 Git 仓库、工作区是否 clean |
| Guard 误拦截 | 检查规则、allowlist、测试 fixture |
| Evidence 缺失 | 检查 writer 调用时机和异常处理 |
| 模型输出失败 | 检查 ModelProvider、Schema 校验和 fallback |

## 10. 测试通过标准

1. P0 测试用例全部真实执行。
2. P0 测试用例全部通过。
3. 无新增回归失败。
4. 测试命令和结果已写入验收结果文档。
5. 失败项已修复或明确标记为阻塞。
6. 不存在伪造测试结果。
