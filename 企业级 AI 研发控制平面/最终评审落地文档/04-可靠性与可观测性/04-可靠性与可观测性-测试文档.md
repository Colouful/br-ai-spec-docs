# 04 可靠性与可观测性 - 测试文档

## 1. 测试目标

验证阶段 04：【可靠性与可观测性】的开发内容是否满足技术实现文档定义的目标、边界和验收标准。

## 2. 测试范围

- 实现 run.log.jsonl 完整事件流
- 实现 checkpoint
- 实现 abort
- 实现 clean
- 实现 resume
- 实现 metrics.json
- 实现命令 timeout 和 retry 策略
- 实现错误码

## 3. 不测试范围

- 不做远程告警系统
- 不做完整 Visual 大屏
- 不做中心化 Runtime
- 不做分布式队列
- 不做多节点执行

## 4. 测试前置条件

1. 当前阶段开发已完成。
2. 前置阶段验收已通过。
3. 当前 Git 工作区状态已记录。
4. 已安装项目依赖。
5. 已确认包管理器和测试命令。
6. 如命令不适配当前项目，必须根据阶段 00 基线结果修正并记录。

## 5. 测试类型

本阶段根据实际改动覆盖以下测试类型：

- 单元测试
- 集成测试
- 回归测试
- 异常测试
- 安全测试
- 兼容性测试
- 可观测性测试
- 回滚测试

| 用例编号 | 测试类型 | 测试场景 | 前置条件 | 操作步骤 | 预期结果 | 优先级 |

## 7. 自动化测试建议

| 测试对象 | 建议位置 | 说明 |
|---|---|---|
| 新增模块单元测试 | `tests/` 或 `src/**/*.test.ts`【待确认】 | 根据当前项目测试框架确定 |
| CLI 集成测试 | `tests/cli/`【待确认】 | 使用临时目录模拟 Git 项目 |
| 文件系统测试 | `tests/fixtures/`【待确认】 | 使用 fixture 避免污染真实项目 |

| 回归测试 | 现有测试目录 | 确保旧功能不破坏 |

## 8. 命令行测试指令

请根据阶段 00 确认结果选择实际命令。

- `br-spec plan "新增产品配置管理模块"`
- `br-spec dry-run`
- `br-spec run`
- `br-spec abort --run <runId>`
- `br-spec clean --stale`
- `br-spec resume <runId>`
- `npm test 或 pnpm test`
- `npm run typecheck 或 pnpm typecheck`

如果项目使用 npm：

- `npm install`
- `npm test`
- `npm run lint`
- `npm run typecheck`
- `npm run build`

如果项目使用 pnpm：

- `pnpm install`
- `pnpm test`
- `pnpm lint`
- `pnpm typecheck`
- `pnpm build`

## 9. 失败排查指南

| 失败类型 | 排查步骤 |
|---|---|
| 类型检查失败 | 查看新增类型、导出路径、tsconfig include/exclude |
| 单元测试失败 | 先确认是否为本阶段改动导致，不允许删除测试 |
| CLI 命令失败 | 查看参数解析、运行目录、配置文件路径 |
| 文件系统测试失败 | 检查临时目录、权限、路径兼容性 |
| Git 相关失败 | 检查当前是否为 Git 仓库、工作区是否 clean |
| Guard 误拦截 | 检查规则、allowlist、测试 fixture |
| Evidence 缺失 | 检查 writer 调用时机和异常处理 |
| 模型输出失败 | 检查 ModelProvider、Schema 校验和 fallback |

## 10. 测试通过标准

1. P0 测试用例全部真实执行。
2. P0 测试用例全部通过。
3. 无新增回归失败。
4. 测试命令和结果已写入验收结果文档。
5. 失败项已修复或明确标记为阻塞。
6. 不存在伪造测试结果。
