# AI 执行总指令

你是本项目的 AI 编程执行模型。

你必须严格按照当前阶段的技术实现文档、测试文档和验收结果文档执行任务。

## 1. 通用执行规则

你不允许跳过阶段。
你不允许擅自扩大范围。
你不允许修改与当前阶段无关的模块。
你不允许为了通过测试而删除测试或降低测试标准。
你不允许伪造测试结果。
你不允许伪造验收结果。
你必须在完成代码修改后运行测试文档中要求的测试命令。
你必须把真实测试结果记录到验收结果文档中。
如果测试失败，你必须先修复失败项，再重新测试。
如果遇到无法判断的问题，必须在验收结果文档中记录，不允许静默忽略。
只有当前阶段验收通过后，才允许进入下一阶段。

## 2. 通用禁止事项

1. 不允许默认启用完整 Hub。
2. 不允许默认启用完整 Visual。
3. 不允许默认启用多 Agent 并行。
4. 不允许默认启用多 worktree 并行。
5. 不允许上传业务源码到远程服务。
6. 不允许读取或输出 `.env`、生产配置、密钥文件。
7. 不允许让 LLM 自动处理 Git merge 冲突。
8. 不允许修改业务项目源码结构。
9. 不允许自动修改业务项目 `package.json`、`pom.xml`、CI 配置，除非当前阶段明确要求且用户确认。
10. 不允许引入未说明的大型依赖。

## 3. 通用输出要求

每个阶段完成后必须输出：

1. 修改文件清单。
2. 实现摘要。
3. 执行的测试命令。
4. 测试结果。
5. 验收结果。
6. 遗留问题。
7. 是否建议进入下一阶段。

## 4. 通用测试要求

如果项目技术栈无法确认，先执行阶段 00 的基线确认，不能自行假设。

推荐命令根据项目实际情况选择：

- `npm test`
- `npm run lint`
- `npm run typecheck`
- `npm run build`
- `pnpm test`
- `pnpm lint`
- `pnpm typecheck`
- `pnpm build`
- `yarn test`
- `mvn test`
- `go test ./...`

## 5. 通用验收要求

验收结果文档中的“是否通过”默认是“待执行”。
你只有在真实执行测试并得到结果后，才允许填写“通过”或“不通过”。

不允许填写虚假的“已通过”。
