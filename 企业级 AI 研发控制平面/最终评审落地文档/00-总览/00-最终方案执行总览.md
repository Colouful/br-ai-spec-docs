# 最终方案执行总览

## 1. 最终开发目标

将当前方案重构为 `br-ai-spec` V0.1 本地最小闭环执行器。

V0.1 的最终可执行链路为：

1. `br-spec init`
2. `br-spec plan "新增产品配置管理模块"`
3. `br-spec dry-run`
4. `br-spec run`
5. `br-spec verify`
6. `br-spec report`

## 2. 总体架构方向

V0.1 不做完整三仓平台化。长期目标仍是企业级 AI 研发控制平面，但当前阶段先完成本地规范执行器。

| 分层 | 模块 |
|---|---|
| 接入层 | CLI、IDE Adapter Lite |
| 本地控制层 | Core Engine、Run Runtime、Checkpoint Manager、Config Manager |
| 规格与上下文层 | OpenSpec Engine、OpenSpec View Builder、Context Engine、Asset Pack Loader |
| AI 模型适配层 | Model Adapter、Prompt Registry Lite、Cost Logger、Fallback Policy |
| 执行隔离层 | Task Runner、Git Worktree Manager、Patch Generator、Deterministic Merge Engine |
| 质量治理层 | Scope Guard、Secret Guard、Dangerous File Guard、Test Gate、Evidence Gate |
| 观测与审计层 | run.log.jsonl、metrics.json、evidence-index.json、final-report.md |

## 3. 分阶段路线

| 阶段 | 目标 |
|---|---|
| 00 项目理解与基线确认 | 不改业务逻辑，确认当前代码结构、环境和测试基线 |
| 01 核心架构骨架调整 | 建立模块边界和基础分层 |
| 02 核心业务链路迁移 | 打通本地核心链路 |
| 03 权限门禁与治理能力 | 补齐 Guard、审批、审计、安全底线 |
| 04 可靠性与可观测性 | 补齐 timeout、checkpoint、abort、clean、metrics、日志 |
| 05 AI模型适配与扩展能力 | 补齐 Model Adapter、Prompt Registry、成本记录、fallback |
| 06 开发者体验与低入侵接入 | 补齐 doctor、quickstart、低入侵接入模式 |
| 07 最终集成回归测试与验收 | 全量集成、回归、安全、性能和最终验收 |

## 4. 总体风险

| 风险 | 应对方式 |
|---|---|
| V0.1 范围继续扩大 | 默认关闭 Hub、Visual、多 Agent、多 worktree 并行 |
| AI 修改范围失控 | 使用 Scope Guard 和 dry-run |
| 敏感信息泄漏 | Secret Guard 默认开启 |
| 测试结果被伪造 | 验收文档只允许记录真实命令和真实结果 |
| worktree 清理失败 | 提供 abort 和 clean |
| OpenSpec 上下文过大 | 使用 openspec-view 和渐进式披露 |
| Model 绑定单一供应商 | 使用 ModelProvider 接口 |

## 5. 总体验收标准

1. 不依赖 `skill-q-platform` 也能本地运行。
2. 不依赖 `br-ai-spec-visual` 也能生成报告。
3. 可以生成 OpenSpec Lite。
4. 可以生成 openspec-view。
5. 可以生成 task plan。
6. 可以使用单 worktree 隔离执行。
7. Guard 能阻断危险操作。
8. Test Gate 失败时任务不能完成。
9. Evidence 完整生成。
10. metrics 记录模型成本、耗时和失败信息。
11. abort 能清理异常现场。
12. 全量回归测试通过后才能进入下一轮平台化开发。
