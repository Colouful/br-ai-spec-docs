# project-execution-docs

## 1. 文档包用途

本文件包是一套“AI 可执行开发任务包”，用于指导 Codex、Claude Code、Cursor Agent、Devin 或其他 AI 编程模型，按照阶段逐步完成 `br-ai-spec` V0.1 重构开发。

本包不是说明性文档，而是执行性文档。每个阶段均包含：

1. 技术实现文档。
2. 测试文档。
3. 验收结果文档。

验收结果文档默认是模板状态，所有“是否通过”均为“待执行”。只有 AI 编程模型真实完成开发、运行测试并记录结果后，才允许填写实际验收结论。

## 2. 如何使用这些文档

推荐使用流程：

1. 先阅读 `00-总览/00-AI执行总指令.md`。
2. 再阅读 `00-总览/00-最终方案执行总览.md`。
3. 按阶段顺序执行，从 `00-项目理解与基线确认` 开始。
4. 每个阶段只交给 AI 编程模型当前阶段目录下的三个文档。
5. 当前阶段验收结果文档未确认通过前，不允许进入下一阶段。

## 3. 推荐执行顺序

| 阶段 | 阶段名称 | 是否必须串行 | 目标 |
|---|---|---:|---|
| 00 | 项目理解与基线确认 | 是 | 确认代码结构、环境、测试基线，不改业务逻辑 |
| 01 | 核心架构骨架调整 | 是 | 建立本地最小闭环模块边界 |
| 02 | 核心业务链路迁移 | 是 | 打通 init → plan → dry-run → run → verify → report |
| 03 | 权限门禁与治理能力 | 是 | 补齐 Guard、审批、审计和安全底线 |
| 04 | 可靠性与可观测性 | 是 | 补齐 checkpoint、abort、clean、metrics、日志 |
| 05 | AI模型适配与扩展能力 | 部分依赖 | 补齐 Model Adapter、Prompt Registry、成本记录 |
| 06 | 开发者体验与低入侵接入 | 部分依赖 | 补齐 doctor、quickstart、低侵入接入路径 |
| 07 | 最终集成回归测试与验收 | 是 | 全量回归、集成、安全、性能和最终验收 |

## 4. 每个阶段的输入和输出

| 阶段 | 输入 | 输出 |
|---|---|---|
| 00 | 当前代码仓库、已有配置和测试脚本 | baseline 报告、测试基线、缺失信息清单 |
| 01 | 阶段 00 基线 | 模块骨架、feature flags、本地 asset-pack、基础 schema |
| 02 | 阶段 01 骨架 | 本地主链路、OpenSpec Lite、task plan、单 worktree、report |
| 03 | 阶段 02 主链路 | Scope/Secret/Dangerous/Evidence Gate、审计记录 |
| 04 | 阶段 02/03 结果 | checkpoint、abort、clean、resume、metrics、日志 |
| 05 | 阶段 01/02 结果 | ModelProvider、Prompt Registry、成本记录、fallback |
| 06 | 阶段 02/04/05 结果 | doctor、quickstart、低入侵配置、中文接入报告 |
| 07 | 阶段 00-06 结果 | 最终回归结果、最终验收报告、试点建议 |

## 5. 如何交给 AI 编程模型执行

每次只交付一个阶段文件夹。例如执行阶段 01 时，只给 AI 编程模型以下文件：

- `01-核心架构骨架调整/01-核心架构骨架调整-技术实现文档.md`
- `01-核心架构骨架调整/01-核心架构骨架调整-测试文档.md`
- `01-核心架构骨架调整/01-核心架构骨架调整-验收结果文档.md`

同时附加 `00-总览/00-AI执行总指令.md`。

## 6. 如何记录测试结果

AI 编程模型必须把真实执行过的测试命令、输出摘要、失败项和修复记录写入当前阶段的“验收结果文档”。

禁止填写未经执行的通过结论。

## 7. 如何判断是否进入下一阶段

只有同时满足以下条件，才允许进入下一阶段：

1. 当前阶段技术实现任务全部完成。
2. 当前阶段测试文档要求的测试已真实执行。
3. 所有 P0 测试通过。
4. 验收结果文档中“是否允许进入下一阶段”被明确填写为“允许”。
5. 无阻塞级遗留问题。

## 8. 注意事项和禁止事项

1. 不允许擅自扩大阶段范围。
2. 不允许跳过测试。
3. 不允许删除测试。
4. 不允许伪造测试结果。
5. 不允许伪造验收结果。
6. 不允许修改与当前阶段无关的模块。
7. 不允许引入未说明的大型依赖。
8. 不允许破坏向后兼容。
9. 不允许让 LLM 自动解决 Git merge 冲突。
10. 不允许默认依赖 `skill-q-platform` 或 `br-ai-spec-visual`。
11. 不允许上传业务源码到远程服务。
12. 不允许读取或输出 `.env`、生产配置、密钥文件。
