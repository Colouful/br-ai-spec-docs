# 06 开发者体验与低入侵接入 - 测试文档

## 1. 测试目标

验证阶段 06：【开发者体验与低入侵接入】的开发内容是否满足技术实现文档定义的目标、边界和验收标准。

## 2. 测试范围

- 实现 br-spec doctor
- 实现 br-spec quickstart
- 实现低入侵接入配置
- 实现中文诊断报告
- 实现示例配置
- 实现最小接入文档
- 实现清理命令确认机制

## 3. 不测试范围

- 不做 IDE 插件完整 UI
- 不做 Web 管理台
- 不做团队 RBAC
- 不强制业务项目改 scripts
- 不默认写入大量文件到业务项目

## 4. 测试前置条件

1. 当前阶段开发已完成。
2. 前置阶段验收已通过。
3. 当前 Git 工作区状态已记录。
4. 已安装项目依赖。
5. 已确认包管理器和测试命令。
6. 如命令不适配当前项目，必须根据阶段 00 基线结果修正并记录。

## 5. 测试类型

本阶段根据实际改动覆盖以下测试类型：

- 单元测试
- 集成测试
- 回归测试
- 异常测试
- 安全测试
- 兼容性测试
- 可观测性测试
- 回滚测试

## 6. 测试用例表

| 用例编号 | 测试类型 | 测试场景 | 前置条件 | 操作步骤 | 预期结果 | 优先级 |
|---|---|---|---|---|---|---|
| 06-C01 | 命令测试 | doctor 诊断 | 阶段 02 通过 | 执行 br-spec doctor | 输出中文诊断报告，不修改源码 | P0 |
| 06-C02 | 接入测试 | local-only 模式 | 空 Git 项目 | 执行 init 选择 local-only | 运行态写入 ~/.br-spec 或 .ai-spec-local，不污染业务 src | P0 |
| 06-C03 | 接入测试 | repo-native-lite 模式 | Git 项目 | 执行 init 选择 repo-native-lite | 只新增 openspec/.ai-spec 最小文件 | P0 |
| 06-C04 | 安全测试 | clean 确认 | 存在 stale run | 执行 br-spec clean --stale | 先展示删除清单，未确认不删除 | P0 |

## 7. 自动化测试建议

| 测试对象 | 建议位置 | 说明 |
|---|---|---|
| 新增模块单元测试 | `tests/` 或 `src/**/*.test.ts`【待确认】 | 根据当前项目测试框架确定 |
| CLI 集成测试 | `tests/cli/`【待确认】 | 使用临时目录模拟 Git 项目 |
| 文件系统测试 | `tests/fixtures/`【待确认】 | 使用 fixture 避免污染真实项目 |
| Guard 测试 | `tests/guards/`【待确认】 | 构造危险 diff 和敏感文件 |
| 回归测试 | 现有测试目录 | 确保旧功能不破坏 |

## 8. 命令行测试指令

请根据阶段 00 确认结果选择实际命令。

- `br-spec init`
- `br-spec doctor`
- `br-spec quickstart`
- `br-spec clean --stale`
- `br-spec abort --run <runId>`
- `npm test 或 pnpm test`
- `npm run build 或 pnpm build`

如果项目使用 npm：

- `npm install`
- `npm test`
- `npm run lint`
- `npm run typecheck`
- `npm run build`

如果项目使用 pnpm：

- `pnpm install`
- `pnpm test`
- `pnpm lint`
- `pnpm typecheck`
- `pnpm build`

## 9. 失败排查指南

| 失败类型 | 排查步骤 |
|---|---|
| 类型检查失败 | 查看新增类型、导出路径、tsconfig include/exclude |
| 单元测试失败 | 先确认是否为本阶段改动导致，不允许删除测试 |
| CLI 命令失败 | 查看参数解析、运行目录、配置文件路径 |
| 文件系统测试失败 | 检查临时目录、权限、路径兼容性 |
| Git 相关失败 | 检查当前是否为 Git 仓库、工作区是否 clean |
| Guard 误拦截 | 检查规则、allowlist、测试 fixture |
| Evidence 缺失 | 检查 writer 调用时机和异常处理 |
| 模型输出失败 | 检查 ModelProvider、Schema 校验和 fallback |

## 10. 测试通过标准

1. P0 测试用例全部真实执行。
2. P0 测试用例全部通过。
3. 无新增回归失败。
4. 测试命令和结果已写入验收结果文档。
5. 失败项已修复或明确标记为阻塞。
6. 不存在伪造测试结果。
