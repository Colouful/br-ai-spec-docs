# V0.1 代码实现设计文档

文档目标：给开发同事或 AI 编码工具提供可执行的实现蓝图。  
重点仓库：br-ai-spec。  
辅助仓库：skill-q-platform、br-ai-spec-visual。

---

## 1. 技术假设

V0.1 默认使用 Node.js / TypeScript 实现 CLI 核心逻辑。如果当前 br-ai-spec 已有技术栈不同，可保持现有栈不变，但模块边界建议保持一致。

核心原则：

1. CLI 与业务项目解耦。
2. 所有协议文件使用 JSON Schema 校验。
3. 所有运行过程写入事件日志。
4. 所有执行动作可恢复、可重放、可审计。
5. 不在 `src/` 目录下生成平台文件。
6. 不上传业务源码，Visual 默认只接收元数据、状态和证据索引。

## 4. CLI 命令实现细节

### 4.1 br-spec init

职责：初始化协议目录和项目配置。

伪代码：

```ts
async function initCommand(options: InitOptions) {
  assertGitRepo();
  const scanResult = await detectStack(process.cwd());
  const projectConfig = buildProjectConfig(scanResult, options);

  await ensureDir('openspec');
  await ensureDir('.ai-spec');
  await ensureDir('.ai-spec-local');

  await writeJson('.ai-spec/project.config.json', projectConfig);
  await writeJson('.ai-spec/context-policy.json', defaultContextPolicy());
  await writeJson('.ai-spec/evidence-policy.json', defaultEvidencePolicy());
  await writeJson('.ai-spec/manifest.lock.json', resolveManifest(options));

  await ensureGitIgnore('.ai-spec-local/');
  await generateIdeAdapters(projectConfig);
}
```

关键校验：

- 如果不是 Git 仓库，提示先初始化 Git。
- 如果 `openspec/` 已存在，不覆盖，只增量补齐。
- 如果 `.ai-spec/` 已存在，需要询问或使用 `--force`。
- 不能修改业务源码目录。

### 4.2 br-spec plan

职责：生成 OpenSpec、Context Pack、Task DAG。

伪代码：

```ts
async function planCommand(requirement: string, options: PlanOptions) {
  const runId = createRunId();
  const taskLevel = classifyTask(requirement);
  const project = await loadProjectConfig();

  const openspecChange = await buildOpenSpecChange(requirement, taskLevel);
  const openspecView = await buildOpenSpecView(openspecChange);

  const selectedAssets = await selectAssets(project, requirement, openspecView);
  const contextPack = await buildRunBundle({
    runId,
    requirement,
    project,
    openspecView,
    selectedAssets
  });

  const taskDag = await buildTaskDag(contextPack);
  await validateTaskDag(taskDag);

  await writeRunFiles(runId, contextPack, taskDag);
  await sendRunEvent('run.planned', { runId });
}
```

### 4.3 br-spec run

职责：调度 Task DAG、创建 worktree、执行 Agent、合并 patch。

伪代码：

```ts
async function runCommand(runId: string) {
  const bundle = await loadRunBundle(runId);
  const taskDag = await loadTaskDag(runId);
  const changeBranch = await createOrCheckoutChangeBranch(bundle);

  while (!taskDagCompleted(taskDag)) {
    const executableTasks = scheduleExecutableTasks(taskDag);

    const worktrees = await Promise.all(
      executableTasks.map(task => createTaskWorktree(runId, changeBranch, task))
    );

    const results = await executorPool.run(worktrees);
    const patches = await Promise.all(results.map(createPatchBundle));

    await mergePatches(changeBranch, patches);
    await writeCheckpoint(runId);
  }
}
```

### 4.4 br-spec verify

职责：执行 Hook、测试门禁、失败修复。

```ts
async function verifyCommand(runId: string) {
  const bundle = await loadRunBundle(runId);

  await runHook('scope-guard', bundle);
  await runHook('dangerous-file-guard', bundle);
  await runHook('secret-guard', bundle);

  const result = await runTestGates(bundle);

  if (!result.ok) {
    await enterRepairLoop(runId, result);
    return;
  }

  await writeEvidenceIndex(runId, result);
  await sendRunEvent('run.verified', { runId });
}
```

## 5. Task DAG 调度算法

### 5.1 并行选择算法

```ts
function scheduleExecutableTasks(taskDag: TaskDag): ExecutorTask[] {
  const pending = taskDag.tasks.filter(t => t.status === 'pending');
  const completedIds = new Set(
    taskDag.tasks.filter(t => t.status === 'completed').map(t => t.taskId)
  );

  const candidates = pending.filter(task =>
    task.dependsOn.every(id => completedIds.has(id))
  );

  const selected: ExecutorTask[] = [];
  const usedWriteSets = new Set<string>();
  const usedLockKeys = new Set<string>();

  for (const task of candidates) {
    if (!task.parallelizable && selected.length > 0) continue;
    if (hasGlobConflict(task.writeSet, usedWriteSets)) continue;
    if (hasLockConflict(task.lockKeys, usedLockKeys)) continue;

    selected.push(task);
    task.writeSet.forEach(p => usedWriteSets.add(p));
    task.lockKeys.forEach(k => usedLockKeys.add(k));
  }

  return selected;
}
```

### 5.2 冲突判断

V0.1 先使用 glob + lockKey 字符串匹配，后续升级为 AST / 依赖图分析。

冲突示例：

```text
api:/product-config 与 api:/product-config 冲突
db:product_config 与 db:product_config 冲突
vuex:productConfig 与 route:/product-config 不一定冲突，但需要策略判断
```

## 6. Git worktree 实现

### 6.1 创建 change branch

```bash
git checkout -b ai/change/{changeSlug}-{date}
```

### 6.2 创建 task branch

```bash
git branch ai/task/{taskSlug} ai/change/{changeSlug}-{date}
```

### 6.3 创建 worktree

```bash
git worktree add ~/.br-spec/worktrees/{repoHash}/{runId}/{taskId} ai/task/{taskSlug}
```

### 6.4 清理 worktree

```bash
git worktree remove ~/.br-spec/worktrees/{repoHash}/{runId}/{taskId}
git worktree prune
```

### 6.5 合并策略

优先：

```bash
git cherry-pick {taskCommit}
```

备选：

```bash
git merge --no-ff ai/task/{taskSlug}
```

兜底：

```bash
git apply patch.diff
```

## 7. Hook 实现细节

### 7.1 Scope Guard

输入：Task writeSet + 实际 diff 文件。

```ts
for (const file of changedFiles) {
  if (!matchesAny(file, task.writeSet)) {
    throw new ScopeViolationError(file);
  }
}
```

### 7.2 Dangerous File Guard

默认高风险文件：

```text
.env
.env.*
application-prod.yml
application-prod.properties
pom.xml
package-lock.json
pnpm-lock.yaml
数据库迁移历史文件
CI/CD 配置
```

策略：

- 删除禁止。
- 修改需高风险确认。
- 读取需脱敏。

### 7.3 Evidence Gate

Run 完成前必须存在：

```text
evidence-index.json
final-report.md
merge-report.md
acceptance-checklist.md
```

L2 / L3 还必须存在：

```text
test-plan.md
test-cases.md
```

## 10. 错误码设计

| E_CONFIG_INVALID | 配置文件校验失败 |
| E_GIT_DIRTY | Git 工作区不干净 |

## 11. 单元测试设计

### 11.1 project-scanner

- 能识别 Vue + Vite。
- 能识别 Vuex。
- 能识别 Spring Boot。
- 能识别 MySQL / Redis / MQ 配置。

### 11.2 task-dag

- dependsOn 未完成时不能调度。
- writeSet 冲突时不能并行。
- lockKeys 冲突时不能并行。
- API Contract 未冻结时前后端不能并行。

### 11.3 worktree

- 能创建 worktree。
- 能写入 worktree-index。
- 能清理成功合并的 worktree。
- 失败 worktree 按策略保留。

### 11.4 hook

- 修改 writeSet 外文件必须失败。
- 删除高风险文件必须失败。
- Evidence 缺失不能完成。

### 11.5 test-gate

- 测试命令失败时进入 repair。
- repair 超过 3 轮失败。
- 通过后写入 evidence-index。
