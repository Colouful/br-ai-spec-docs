## 一、什么是工作流

### 1.1 概念定义

**工作流（Workflow）** 是一系列可执行指令的集合，用于实现业务逻辑或完成特定任务。它为应用/智能体的数据流动和任务处理提供了一个结构化框架。

工作流的核心在于 **将大模型的强大能力与特定的业务逻辑相结合**，通过系统化、流程化的方法来实现高效、可扩展的 AI 应用开发。

> 如果把 AI 应用比作一家工厂，那么工作流就是工厂里的**流水线**——原材料（输入数据）从一端进入，经过各个工位（节点）的加工处理，最终产出成品（输出结果）。

### 1.2 工作流 vs 传统编程

| 维度 | 传统编程 | 工作流 |
|------|---------|--------|
| 开发门槛 | 需要编写代码 | 可视化拖拽，低代码/零代码 |
| 灵活性 | 高度灵活，但开发周期长 | 快速搭建，即时调试 |
| 可维护性 | 依赖代码质量 | 可视化流程，一目了然 |
| 适用人群 | 专业开发者 | 业务人员、运营、产品经理 |
| 迭代速度 | 慢（需部署上线） | 快（实时测试、即时发布） |

### 1.3 为什么需要工作流

- **复杂任务拆解**：将复杂的 AI 任务拆分为多个可管理的子任务
- **流程可控**：每个步骤的输出都可被精确控制和验证
- **模块化复用**：节点可以复用，工作流可以嵌套
- **人机协作**：在关键节点引入人工审核，确保输出质量
- **自动化执行**：设定触发条件后，工作流可以自动运行

## 二、工作流的核心要素

### 2.1 节点（Node）

节点是工作流的基本组成单元，每个节点代表一个独立的处理步骤。常见节点类型包括：

| 节点类型 | 功能说明 | 典型示例 |
|---------|---------|---------|
| **触发器节点** | 启动工作流的条件 | 手动触发、定时触发、事件触发 |
| **输入/输出节点** | 接收用户输入或返回结果 | 开始节点、结束节点 |
| **大模型节点** | 调用 AI 大模型进行推理 | GPT、DeepSeek、豆包等 |
| **插件节点** | 调用外部工具或 API | 天气查询、搜索引擎、图像生成 |
| **逻辑节点** | 控制流程走向 | 条件判断（IF）、循环、选择器 |
| **数据处理节点** | 对数据进行转换和加工 | 文本处理、代码执行、变量设置 |
| **知识库节点** | 检索和引用私有知识 | 企业文档、产品手册 |

### 2.2 连接（Edge）

连接定义了节点之间的数据流向。通过连接，上游节点的输出可以作为下游节点的输入，形成完整的数据管道。

### 2.3 变量（Variable）

变量用于在节点之间传递数据。工作流支持：

- **全局变量**：在整个工作流中可访问
- **局部变量**：仅在特定节点或作用域内有效
- **环境变量**：存储 API 密钥等敏感信息

### 2.4 触发机制

| 触发方式 | 说明 | 适用场景 |
|---------|------|---------|
| 手动触发 | 用户主动点击运行 | 测试、一次性任务 |
| 定时触发 | 按 Cron 表达式定时执行 | 日报生成、数据同步 |
| 事件触发 | 特定事件发生时自动触发 | 收到消息、数据变更 |
| API 触发 | 通过接口调用触发 | 系统集成、第三方调用 |

## 三、工作流的典型使用场景

### 3.1 内容创作与营销

**场景描述**：自动化生成各类营销内容

| 子场景 | 工作流示例 |
|-------|-----------|
| 短视频脚本生成 | 输入主题 → 大模型生成文案 → 分镜描述 → 语音合成 → 视频合成 |
| 社交媒体运营 | 热点抓取 → 内容生成 → 多平台适配 → 定时发布 |
| 电商商品文案 | 商品参数输入 → 卖点提炼 → 多风格文案生成 → 图文排版 |

### 3.2 智能客服与问答

**场景描述**：构建能够理解用户意图、检索知识、给出精准回答的智能客服系统

```
用户提问 → 意图识别 → 知识库检索 → 大模型组织答案 → 输出回复
                ↓
            意图不匹配 → 转人工/兜底回复
```

### 3.3 数据分析与报告

**场景描述**：自动化数据采集、分析和报告生成

```
定时触发 → 数据采集（API/爬虫） → 数据清洗（代码节点） → 分析计算 → 报告生成（大模型） → 推送通知
```

### 3.4 办公自动化

| 应用场景 | 流程示例 |
|---------|---------|
| 会议纪要整理 | 录音转文字 → 要点提取 → 待办事项识别 → 格式化输出 |
| 邮件自动回复 | 邮件接收 → 内容分析 → 分类判断 → 生成回复草稿 → 发送 |
| 合同审查 | 文档上传 → 关键条款提取 → 风险识别 → 审查报告生成 |

### 3.5 教育培训

- **个性化学习路径**：评估测试 → 能力分析 → 学习资源推荐 → 进度跟踪
- **自动批改系统**：答案提交 → 标准答案比对 → 评分 → 错题解析生成

### 3.6 研发辅助

- **代码审查**：代码提交 → 静态分析 → 大模型审查 → 修改建议生成
- **API 文档生成**：代码解析 → 接口信息提取 → 文档模板填充 → 格式输出

## 四、扣子（Coze）工作流概述

### 4.1 平台简介

**扣子（Coze）** 是字节跳动推出的 AI 智能体开发平台，提供可视化工作流搭建界面，让普通人也能轻松创建自动化 AI 流水线。

**核心特点**：

- 🎨 **可视化画布**：拖拽式节点搭建，所见即所得
- 🤖 **多模型支持**：集成 DeepSeek、豆包、GPT 等大模型
- 🔌 **丰富插件**：60+ 官方插件，覆盖搜索、图像、语音、视频等领域
- 📚 **知识库集成**：支持上传文档构建私有知识库
- 🚀 **一键发布**：可发布到微信、抖音、飞书、豆包等平台
- 🔄 **实时调试**：画布内直接测试，即时查看每个节点的输出

### 4.2 扣子工作流的两种类型

| 类型 | 英文名 | 适用场景 | 特点 |
|------|--------|---------|------|
| **工作流** | Workflow | 功能类请求 | 顺序执行一系列节点实现某个功能，适合数据自动化处理 |
| **对话流** | Chatflow | 对话类请求 | 基于对话场景的特殊工作流，支持多轮交互，适合 Chatbot |

### 4.3 扣子工作流的优势

1. **零代码门槛**：无需编程基础，业务人员也能搭建复杂 AI 应用
2. **大模型原生**：深度集成大模型能力，每个节点都可调用 AI
3. **生态丰富**：插件市场持续扩展，覆盖绝大多数业务场景
4. **多模态支持**：文本、图像、音频、视频一站式处理
5. **企业级能力**：支持团队协作、版本管理、权限控制

## 五、扣子工作流创建超详细流程

### 5.1 准备工作

#### 5.1.1 注册与登录

1. 访问扣子官网：**https://www.coze.cn**
2. 使用手机号注册/登录
3. 进入个人工作空间

#### 5.1.2 选择开发平台

扣子提供两个开发平台：

- **扣子 Coze**：国内版，功能全面，适合国内用户
- **Coze 国际版**：面向海外用户

> 本文以国内版（coze.cn）为例进行说明。

### 5.2 创建第一个工作流

#### 步骤 1：进入工作流编辑器

1. 登录后，点击左侧菜单的 **"工作空间"**
2. 选择 **"资源库"** 标签
3. 点击右上角的 **"+ 资源"** 按钮
4. 选择 **"工作流"**

#### 步骤 2：填写工作流基本信息

| 字段 | 填写说明 | 示例 |
|------|---------|------|
| **工作流名称** | 只支持字母、数字和下划线，以字母开头 | `DailyWeatherReport` |
| **工作流描述** | 给大模型看的，说明工作流的功能和调用时机 | "根据城市名称获取当天天气并生成报告" |

> ⚠️ **重要**：工作流描述非常重要！当 Bot 决定调用哪个工作流时，会参考这个描述。描述要清晰、准确，包含触发条件和输出内容。

#### 步骤 3：认识工作流画布

创建成功后，进入工作流编辑界面，你会看到：

- **左侧节点面板**：所有可用的节点类型
- **中间画布区域**：拖拽搭建工作流的主区域
- **右侧配置面板**：选中节点后，在此配置参数
- **顶部工具栏**：保存、测试、发布等操作按钮

画布默认包含两个节点：
- 🟢 **开始节点**（绿色）：工作流的入口
- 🔴 **结束节点**（红色）：工作流的出口

### 5.3 节点配置详解

#### 5.3.1 开始节点配置

开始节点用于设定启动工作流需要的输入信息。

**默认参数**：
- `BOT_USER_INPUT`：用户在本轮对话中输入的原始内容

**自定义参数添加方法**：

1. 点击开始节点，右侧展开配置面板
2. 点击 **"+ 添加参数"**
3. 填写参数信息：

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 参数名 | 变量的标识符 | `city` |
| 参数类型 | 数据类型（字符串/数字/布尔/图片等） | `String` |
| 描述 | 参数用途说明 | "目标城市名称" |
| 是否必填 | 是否必须提供该参数 | ✅ 勾选 |
| 默认值 | 未输入时的默认值 | `北京` |

> 💡 **技巧**：对于图片类型的输入，可以上传示例图片，帮助系统理解输入格式。

#### 5.3.2 大模型节点配置

大模型节点是工作流的核心，用于调用 AI 进行推理。

**配置步骤**：

1. 从左侧面板拖拽 **"大模型"** 节点到画布
2. 连接上游节点（如开始节点）
3. 在右侧面板进行配置：

| 配置项 | 说明 | 建议 |
|--------|------|------|
| **模型选择** | 选择底层大模型 | 通用任务选豆包/DeepSeek；创意任务选 GPT-4 |
| **温度值** | 控制输出随机性（0-1） | 0.2 适合确定性任务；0.8 适合创意任务 |
| **最大 Token** | 限制输出长度 | 根据任务需求设置，避免过长或过短 |
| **系统提示词** | 设定模型的角色和行为规范 | 详细描述模型应该扮演的角色和遵循的规则 |
| **用户提示词** | 具体的任务指令 | 使用 `{{变量名}}` 引用上游节点的输出 |

**提示词编写示例**：

```
【系统提示词】
你是一位专业的天气预报分析师。请根据提供的天气数据，
生成一份简洁、易懂的天气报告，包含温度、天气状况和出行建议。

【用户提示词】
请根据以下天气数据生成报告：
城市：{{city}}
温度：{{temperature}}℃
天气状况：{{condition}}
湿度：{{humidity}}%
```

#### 5.3.3 插件节点配置

扣子提供丰富的插件库，涵盖搜索、图像、语音、工具等多个类别。

**添加插件步骤**：

1. 点击节点后的 **"+"** 号
2. 选择 **"插件"** 类型
3. 在插件市场中搜索需要的插件（如"必应搜索"、"天气查询"）
4. 点击添加

**插件配置要点**：

- **输入参数**：填写插件需要的参数，可引用上游节点输出
- **输出参数**：插件执行后返回的数据字段
- **API 密钥**：部分插件需要配置密钥（在平台设置中添加）

#### 5.3.4 代码节点配置

代码节点允许使用 Python 或 Node.js 编写自定义逻辑。

**使用场景**：
- 数据格式转换
- 复杂计算
- 字符串处理
- 条件逻辑判断

**配置方法**：

1. 添加 **"代码"** 节点
2. 在 IDE 中编写代码
3. 定义输入变量（引用上游输出）
4. 定义输出变量（供下游节点使用）

**示例代码**（Python）：

```python
# 输入参数：score（分数）
# 输出参数：grade（等级）

def main(args):
    score = args.get("score", 0)
    if score >= 90:
        grade = "优秀"
    elif score >= 80:
        grade = "良好"
    elif score >= 60:
        grade = "及格"
    else:
        grade = "不及格"

    return {"grade": grade}
```

#### 5.3.5 选择器节点配置

选择器节点用于条件分支判断，类似于编程中的 `if-else`。

**配置步骤**：

1. 添加 **"选择器"** 节点
2. 设置判断条件：
   - 选择判断的变量
   - 选择比较运算符（等于/不等于/大于/包含等）
   - 填写比较值
3. 添加多个分支（点击 **"+"** 添加分支）
4. 设置分支优先级（拖拽调整顺序）

> ⚠️ **注意**：选择器的分支是有优先级的，排在上面的分支会先被判断。如果多个条件都可能满足，请确保优先级设置正确。

#### 5.3.6 文本处理节点配置

文本处理节点用于对字符串进行拼接、转义、提取等操作。

**常见功能**：
- 字符串拼接
- 正则表达式提取
- 文本替换
- JSON 格式化

#### 5.3.7 知识库节点配置

知识库节点用于从上传的文档中检索相关信息。

**配置步骤**：

1. 提前在 **"知识库"** 中上传文档（支持 PDF、Word、TXT 等）
2. 在工作流中添加 **"知识库"** 节点
3. 选择要检索的知识库
4. 设置检索参数：
   - 检索模式（语义检索/全文检索）
   - 返回结果数量
   - 相似度阈值

#### 5.3.8 结束节点配置

结束节点用于返回工作流的运行结果。

**配置方法**：

1. 点击结束节点
2. 在右侧面板配置输出参数：
   - **参数名**：返回结果的字段名
   - **参数值**：引用上游节点的输出（使用 `{{节点名.输出参数}}`）

**输出模式选择**：
- **返回文本**：直接返回文本内容
- **返回图片**：返回图片 URL 或 Base64
- **返回卡片**：返回结构化数据

### 5.4 节点连接与数据流

#### 5.4.1 连接规则

1. 点击节点右侧的输出端点
2. 拖拽到下一个节点的输入端点
3. 松开鼠标完成连接

#### 5.4.2 数据引用语法

在节点配置中引用上游数据时，使用以下语法：

```
{{节点名称.输出参数名}}
```

**示例**：
- `{{开始.city}}`：引用开始节点的 city 参数
- `{{必应搜索.results}}`：引用必应搜索节点的 results 输出
- `{{大模型_1.output}}`：引用大模型节点的 output 输出

#### 5.4.3 数据类型匹配

连接节点时，确保数据类型匹配：

| 上游输出类型 | 可连接的下游输入类型 |
|-------------|-------------------|
| String | String, Text, Any |
| Number | Number, String, Any |
| Image | Image, File, Any |
| Array | Array, Any |
| Object | Object, Any |

### 5.5 测试与调试

#### 5.5.1 试运行

1. 点击右上角的 **"试运行"** 按钮
2. 填写开始节点需要的输入参数
3. 点击 **"运行"**
4. 查看每个节点的执行结果

#### 5.5.2 调试技巧

- **查看节点输出**：点击已运行的节点，查看输入和输出数据
- **添加消息节点**：在关键位置添加消息节点，输出中间结果
- **检查红色提示**：如果节点配置不完整，会显示红色文字提示
- **查看运行日志**：点击日志按钮，查看详细的执行日志

#### 5.5.3 常见错误排查

| 错误现象 | 可能原因 | 解决方法 |
|---------|---------|---------|
| 节点显示红色 | 配置不完整 | 检查必填参数是否已填写 |
| 数据引用失败 | 变量名拼写错误 | 核对节点名称和参数名 |
| 插件调用失败 | API 密钥未配置 | 在设置中配置 API 密钥 |
| 大模型输出不符合预期 | 提示词不清晰 | 优化系统提示词和用户提示词 |
| 选择器分支未触发 | 条件设置错误 | 检查条件运算符和值 |

### 5.6 保存与发布

#### 5.6.1 保存工作流

1. 点击右上角的 **"保存"** 按钮
2. 系统会自动保存当前版本

#### 5.6.2 发布工作流

1. 测试无误后，点击 **"发布"**
2. 选择发布范围：
   - **仅自己可见**：私密使用
   - **团队可见**：分享给团队成员
   - **公开发布**：发布到平台供他人使用

#### 5.6.3 在 Bot 中使用工作流

1. 创建或编辑一个 Bot
2. 在 **"技能"** 区域点击 **"添加工作流"**
3. 选择已发布的工作流
4. 在提示词中说明何时调用该工作流

## 六、扣子工作流核心节点详解

### 6.1 节点类型总览

| 分类 | 节点名称 | 功能描述 |
|------|---------|---------|
