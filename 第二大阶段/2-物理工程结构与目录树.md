# 二、物理工程结构与目录树

> 本章节定义三个核心仓库、目标业务项目、本地全局缓存、IDE 注入目录、运行产物目录的完整物理结构。
> 所有后续开发必须严格遵循此目录边界，不允许随意新增混乱目录。

---

# 2.1 总体物理结构

整体工程由 5 类物理空间组成：

```text
workspace-root/
├── skill-q-platform/           # AI 工程资产 Hub，资产管理、生成、审核、发布
├── br-ai-spec/                 # CLI 执行引擎，项目初始化、扫描、上下文构建、状态机、执行器适配
├── br-ai-spec-visual/          # 运行态可视化与团队治理平台
├── target-business-project/    # 被接入的业务项目，生成轻量索引、锁文件、Overlay
└── ~/.ai-spec-auto/            # 用户本地全局缓存、运行日志、资产缓存、原始上下文
```

逻辑关系：

```text
skill-q-platform
    ↓ 提供 Manifest / Asset / Agent Profile / Tech Profile
br-ai-spec
    ↓ 安装轻量索引、构建上下文、调度执行器
target-business-project
    ↓ 运行数据、需求记录、锁文件
br-ai-spec-visual
    ↓ 展示项目画像、运行态、治理数据
~/.ai-spec-auto
    ↓ 缓存 Hub 资产正文、运行日志、原始上下文
```

## 2.6.2 缓存原则

```text
1. Hub 资产正文只缓存到 ~/.ai-spec-auto/cache/assets。
2. 项目内只保存 index 和 checksum。
3. 本地运行原始日志只保存到 ~/.ai-spec-auto/runs。
4. 上传 Visual 前必须脱敏和摘要化。
5. 删除缓存后，sync 必须能从 Hub 恢复。
```
