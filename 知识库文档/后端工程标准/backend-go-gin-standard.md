# Go Gin 后端工程标准

## 适用技术栈

- **语言**：Go 1.22+（`go.mod` 中 `go` 行与组织基线一致），`gofmt`、`go vet` 与 `golangci-lint` 在 CI 中必跑，保证可复现。
- **框架**：Gin 作为 HTTP 路由、中间件与 `Context` 参数绑定面；用例、领域与事务放在不直接依赖 `*gin.Context` 的业务包中（如 `internal/service`），`handler` 仅作适配，便于单测与替换实现。
- **构建**：`go build` 产出单二进制；`go.sum` 提交版本控制；**敏感**配置不写入仓库，经环境变量、密钥服务或只读挂载注入。
- **运行环境**：容器或进程管理；`GIN_MODE`、读/写超时、限流与可观测性（结构日志、指标、trace 中间件）与组织标准一致。

## 适用项目类型

- **application**：`cmd/<app>/main` 可执行体，提供 HTTP、健康/就绪、指标等端点；对外路径与鉴权在文档中唯一说明。
- **service**：单体或按包划分子域；Gin 为入站适配器，**不**承载领域规则，领域在纯 Go 包中实现。
- **microservice**：多部署单元，经 HTTP/gRPC/消息解耦；**不**以进程内可写单例作为业务正确性来源。
- **monorepo**：单 `go.mod` 或 `go work` 多模块；**禁止**为走捷径产生循环 `import`；公共库不反向依赖具体应用包。

## 项目结构规范

- `internal/handler` 或 `api`：注册路由、binding、调用用例/服务，不写长 SQL、不承载业务分支。
- `internal/service` / `usecase`：用例编排、错误码映射、**事务**（`sql.Tx` 或 ORM 事务）与**外部**调用顺序与补偿策略。
- `internal/repository` / `store`：数据访问，可为 sqlx、GORM、ent、sqlc 等，**仅**负责查询、持久化与行映射。
- `internal/model` 与对外的 DTO：请求/响应/持久化分类型；**禁止**在 JSON 中无控制地暴露全部表字段，除非有显式白名单与评审。
- `internal/middleware`：鉴权、请求 ID、日志、超时、限流、恢复（`Recovery`）。
- `cmd/<app>/main`：依赖组装、注册路由、启动与优雅关闭（`Shutdown` 超时可配置）。

## Controller 规范

- 职责：解析 Path/Query/Body（`ShouldBindJSON` 等），调用 Service，以统一结构体写 `c.JSON` 或 `c.AbortWithStatusJSON`；**禁止**在 Handler 中开闭事务或写大段业务。
- 参数：为每个 API 定义 `struct` 与 `binding` 标签；文件、分页、游标、排序使用专用类型，命名一致。
- 响应：若项目有统一成功/错误体，全项目一致；分页、游标字段名固定，与客户端契约对齐。
- 状态码：201 与 `Location` 用于创建；4xx/5xx 的语义在《API 设计》中唯一定义。业务可预期失败与协议错误区分清楚（4xx+子码 或 200+业务 code 二选一并贯彻）。
- 校验边界：简单规则在 `binding` 与自定义 tag；跨资源、跨表规则在 Service/领域层。

## Service 规范

- 用例在 Service 中：接收已解析的值或 DTO，返回业务结果与可映射的**领域**错误，不泄漏 ORM/驱动细节到 Handler。
- **事务边界**在此层；多次写操作在同一 `Tx` 内完成；长事务分片与失败回滚有设计说明。
- 外部 HTTP/消息/缓存调用带**超时、重试上界、冪等键、熔断/降级**选项，配置或代码可审计，不在路由里写裸长调用。

## DTO / VO / Entity 规范

- 请求/响应/列表项各自定义 `struct` 或独立包，与 OpenAPI/客户端契约一一对应。
- 持久化模型在 `model` 或 `db` 包，**禁止**将含内部字段的 ORM 结构体直接作为**唯一**公网 JSON 源，除非有显式转换层与字段白名单。
- 内部分页、任务载荷可用内部类型，不进入公开文档时注明范围。

## Repository / Mapper 规范

- 查询、聚合、行映射在 `repository` 中；**禁止**在 Handler 中直接 `db.Exec` 大段 SQL（已评审的报表/运维模块可例外并登记）。
- 数据层**不含**业务 if-else 大分支，仅做数据通道；N+1 用 `Preload`、子查询、连接策略等显式处理。

## 异常处理

- 使用 `middleware`+`errors`+可映射的**业务**错误类型，统一为 HTTP+body+trace；不向客户端返回堆栈与内网信息。
- `gin` 的 `c.Error` 与全局处理配合时，**错误链**在日志中可展开，**响应体**不复制敏感内部错误。
- 外呼失败区分可重试与不可重试，日志带上游名与**脱敏**的关联 id。

## 参数校验

- 必填、类型、范围、长度、格式、嵌套、切片、联合与枚举在 `binding` 与自定义验证器；跨字段在 Service/领域或集中校验函数。
- 与唯一约束、状态机冲突在 Service/Repository 映射为文档化的 409/422 等，避免裸 500。

## 日志规范

- 使用 `slog`、zap 等**结构化**日志，贯穿 `request_id`；密码、Token、全量 PII 不打明文。
- 审计与业务操作可区分 `level` 与输出目标，满足留存与合规。

## 权限规范

- 鉴权在 `middleware` 与依赖注入中**集中**实现；各路由用中间件/路由组声明，不复制分散的鉴权 if。
- 数据权限在查询中注入租户/数据范围，**禁止**在多处手写不可审计的特判 `WHERE`。
- 服务间 mTLS/服务账户/Token 轮换有 Runbook 与配置清单。

## 事务规范

- 单库：在 Service 中显式 `Begin`/`Commit`/`Rollback` 或使用 ORM 事务 API；**禁止**在 Handler 中管理事务。
- 冪等：唯一键、冪等表、冪等头；分布式用 Saga、发件箱、最终一致，不默认 2PC 跨异构资源。
- 重试仅对瞬时错误，写路径重试须有冪等保障与上界。

## 测试规范

- 单元：`testing`+mock 接口，覆盖领域与**分支**；`handler` 用 `httptest`+mock service。
- 集成：Testcontainers 或**等价**依赖；**迁移**策略与线上一致或评审过的子集。
- 可选：契约测试、关键路径 E2E；CI 中 `go test`+lint+竞态检测（`-race`）按策略必过或登记例外。

## Rule 生成要求

- **约束**：`internal` 对外部库隐藏实现细节、无环 import、**敏感**配置不入库、**禁止** `recover` 后静默成功、外呼带超时。
- **禁止行为**：在 Handler 写大段业务、多处不一致校验、对外返回 `err.Error()` 中的内部细节、日志打印密钥。
- **验收标准**：`go test` 与 `golangci-lint` 在 CI 全绿，OpenAPI 与实现可对照，依赖漏洞/许可证不突破门槛或有例外单。

## Skill 生成要求

- **输入**：功能范围、子域/包建议、NFR 与合规模块、已有错误码与 OpenAPI 基线。
- **步骤**：定路由与 DTO 契约；实现 `service`+`repository`+事务；接 `handler`+中间件；单测与集成；更新文档与 Runbook 片段（无虚构 URL）。
- **输出**：可 `go run` 的目录结构、`.env.example` 仅**示例**、**无** 生产密钥、异常与补偿路径说明。
- **异常处理**：写清回滚、消息重试、死信、人工对账的边界。

## Flow 生成要求

- **阶段**：契约与模型评审、实现、自测、Code Review、分环境发布、可观测与告警验收、压测/故障演练。
- **门禁**：format、lint、单测、集成、SAST/依赖扫描、数据迁移在流水线中的策略。
- **状态**：任务/版本/缺陷与发布单、变更记录关联；配置与 Schema 协同演进。
- **异常出口**：回滚、只读/降级、补偿任务、人工对账与 hotfix 策略。

## Manifest 推荐

- **推荐资产组合**：`golang-gin-base-rules`、OpenAPI 生成/校验、多阶段 `Dockerfile`、OpenTelemetry 或组织标准可观测方案。
- **安装策略**：在 `go.mod` 中锁定 Gin 与核心依赖的**大版本**与最低 Go 版本；不在 Skill 中写死私有模块代理凭据与生产环境 URL。

## 禁止行为

- **禁止**将大段「可直接用于生产」的完整业务实现作为唯一交付物且未经评审；**禁止**虚构不存在的内部服务地址、认证方式、租户与权限模型。
- **禁止**在文档或技能中要求提供、收集或固化生产密钥、证书私钥、数据库高权限凭据；使用占位符与密钥管理说明即可。

## 验收标准

- 可复现执行 `go test` 与 `go build`；环境变量与密钥来源分离。API 行为可用测试与 OpenAPI/文档相互验证。敏感信息不入业务库、不出现在未脱敏的明文日志中。
