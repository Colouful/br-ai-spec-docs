# 四仓最终架构说明

## 1. 架构定位

V0.1 四仓架构由本地执行控制面、运行态观测面、资产中心和文档中心组成。四仓之间通过 Schema(模式)、Fixture(样例数据)、AssetPackage(资产包)、RunEvent(运行事件)、EvidenceReport(证据报告) 和 AssetUsageFeedback(资产使用反馈) 对接。

## 2. br-ai-spec 职责

`br-ai-spec` 是本地执行控制面，职责包括：

1. CLI(命令行工具) 初始化和同步。
2. 从 Hub(资产中心) 搜索、安装、同步、升级和回滚资产。
3. 生成 manifest(清单) 和 lock(锁文件)。
4. 生成 Cursor(开发工具) / Claude Code(开发工具) 项目文件。
5. 执行最小 Run(运行) 并输出 RunEvent(运行事件) 与 EvidenceReport(证据报告)。
6. 通过 Visual Connector(可视化连接器) 上报运行态。
7. 通过 Hub Connector(资产中心连接器) 回传 AssetUsageFeedback(资产使用反馈)。
8. 输出 `contracts/schemas` 和 `contracts/fixtures`。

`br-ai-spec` 不负责实现 Visual(可视化) 页面，也不负责实现 Asset Hub(资产中心) 后台主体能力。

## 3. br-ai-spec-visual 职责

`br-ai-spec-visual` 是运行态观测面，职责包括：

1. 提供 Collector API(采集接口)。
2. 接收 RunEvent(运行事件)。
3. 接收 EvidenceReport(证据报告)。
4. 生成 Run Timeline(运行时间线) 视图模型。
5. 展示 Hook/Test/Repair/Review(钩子/测试/修复/评审)。
6. 展示 Agent(代理) 协作、质量指标和风险审计摘要。
7. 使用 PrivacyGuard(隐私守卫) 拦截敏感信息。

当前 Collector Store(采集存储) 为内存 Map(映射表)，后续需要持久化。

## 4. skill-q-platform 职责

`skill-q-platform` 是 Asset Hub(资产中心)，职责包括：

1. 管理 HubAsset(资产模型) 和 HubAssetVersion(资产版本)。
2. 提供资产搜索、详情和 AssetPackage(资产包) 元数据。
3. 提供版本列表和回滚元数据。
4. 支持审核、发布和废弃。
5. 支持 Fork(派生) / Override(覆盖) / 继承。
6. 接收 AssetUsageFeedback(资产使用反馈)。
7. 计算 usageCount(使用次数)、successRate(成功率)、failureRate(失败率)、adoptionRate(采纳率)、riskScore(风险分) 和 qualityScore(质量分)。

当前 AssetUsageFeedback(资产使用反馈) 使用内存反馈存储，后续需要持久化。

## 5. br-ai-spec-docs 职责

`br-ai-spec-docs` 是四仓方案文档中心，职责包括：

1. 维护四仓职责边界。
2. 维护联调验收报告。
3. 维护团队快速上手指南。
4. 维护已知问题与后续路线。
5. 维护版本发布检查清单。
6. 标记旧文档与 V0.1 当前实现的关系。

## 6. 数据流

数据流围绕三类数据展开：

1. 资产数据：从 `skill-q-platform` 输出 AssetPackage(资产包)，由 `br-ai-spec` 安装并写入本地 manifest(清单) / lock(锁文件)。
2. 运行数据：由 `br-ai-spec` 产生 RunEvent(运行事件) 和 EvidenceReport(证据报告)，上报到 `br-ai-spec-visual`。
3. 反馈数据：由 `br-ai-spec` 或 Visual(可视化) 链路形成 AssetUsageFeedback(资产使用反馈)，回传 `skill-q-platform` 计算质量指标。

## 7. 控制流

控制流由 `br-ai-spec` 发起：

1. 用户在业务项目执行 `br-ai-spec` CLI(命令行工具)。
2. CLI(命令行工具) 调用 Hub Connector(资产中心连接器) 获取资产。
3. CLI(命令行工具) 生成项目级文件。
4. CLI(命令行工具) 执行最小 Run(运行)。
5. CLI(命令行工具) 调用 Visual Connector(可视化连接器) 上报运行态。
6. CLI(命令行工具) 调用 Hub Connector(资产中心连接器) 回传资产使用反馈。

## 8. 资产流

```text
skill-q-platform 发布 Rule(规则) 资产
  -> 资产搜索
  -> AssetPackage(资产包)
  -> br-ai-spec hub install(资产安装)
  -> manifest(清单) / lock(锁文件)
  -> Cursor(开发工具) / Claude Code(开发工具) 文件
```

资产流的安全边界：

1. Hub(资产中心) 只输出资产包和元数据，不写业务项目文件。
2. `br-ai-spec` 负责写入业务项目受管目录。
3. checksum(校验和) 用于安装校验和回滚判断。

## 9. 运行态观测流

```text
br-ai-spec 执行 Run(运行)
  -> RunEvent(运行事件)
  -> EvidenceReport(证据报告)
  -> br-ai-spec-visual Collector API(采集接口)
  -> Timeline(时间线) / Metrics(指标) / Risk(风险)
```

运行态观测流的安全边界：

1. 不采集完整源码。
2. 不采集原始 Prompt(提示词)。
3. 不采集原始响应。
4. 不采集密钥、token(令牌)、password(密码)、secret(密钥)。
5. 文件路径只允许相对路径和摘要。

## 10. 反馈闭环

```text
Run(运行) 关联 usedAssets(已用资产)
  -> AssetUsageFeedback(资产使用反馈)
  -> skill-q-platform feedback(反馈) 接口
  -> usageCount(使用次数) / successRate(成功率) / qualityScore(质量分)
  -> Hub(资产中心) 资产质量指标
```

反馈闭环当前可用于 V0.1 试点，但因反馈存储仍为内存实现，不应作为长期生产统计依据。

## 11. 安全边界

| 边界 | 规则 |
| --- | --- |
| 源码 | 不上传完整源码。 |
| Prompt(提示词) | 不上传 rawPrompt(原始提示词)。 |
| 响应 | 不上传 rawResponse(原始响应)。 |
| 路径 | 不上传绝对路径，changedFiles(变更文件) 只保留相对路径和摘要。 |
| 密钥 | 不上传 token(令牌)、password(密码)、secret(密钥)、apiKey(接口密钥)。 |
| Override(覆盖) | 禁止覆盖 checksum(校验和)、content(正文)、status(状态)、publishedAt(发布时间) 等核心字段。 |
