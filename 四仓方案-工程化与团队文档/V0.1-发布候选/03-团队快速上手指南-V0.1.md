# 团队快速上手指南 V0.1

## 1. 使用边界

本指南基于 V0.1 发布候选当前实现。它不再沿用旧的“只扫描业务项目展示 Manifest(清单)”链路，而是以 AssetPackage(资产包)、manifest(清单) / lock(锁文件)、RunEvent(运行事件)、EvidenceReport(证据报告)、Visual Timeline(可视化时间线) 和 AssetUsageFeedback(资产使用反馈) 为最小闭环。

本指南中的命令需要在团队本地环境按实际仓库脚本确认后执行；本文不声称本轮已重新执行这些命令。

## 2. 准备仓库

建议目录结构：

```text
workspace/
├── skill-q-platform
├── br-ai-spec
├── br-ai-spec-visual
└── demo-project
```

## 3. 启动 skill-q-platform

`skill-q-platform` 是 Asset Hub(资产中心)，负责发布资产、输出 AssetPackage(资产包)、接收 AssetUsageFeedback(资产使用反馈) 并计算质量指标。

常规启动顺序：

```bash
cd skill-q-platform
pnpm install
pnpm prisma generate
pnpm dev
```

如果本地项目使用 `npm`，以 `package.json` 中实际脚本为准。

## 4. 发布 Rule 资产

在 `skill-q-platform` 中创建并发布 Rule(规则) 资产。最小资产建议包含：

| 字段 | 示例 |
| --- | --- |
| 名称 | 前端编码规范 |
| 标识 | `frontend-coding-standard` |
| 类型 | `rule` |
| 版本 | `1.0.0` |
| 状态 | `published`，外部接口兼容为 `active` |
| 适用技术栈 | React(前端框架) / TypeScript(类型脚本) |

V0.1 验收材料已覆盖 active Rule(启用规则) 资产的发布、搜索和后续安装链路。

## 5. 获取 AssetPackage

通过 Hub(资产中心) 获取 AssetPackage(资产包)。V0.1 已验证的包元数据包括：

1. `assetId`：资产标识。
2. `assetType`：资产类型，例如 `rule`。
3. `name`：资产名称。
4. `version`：版本。
5. `source`：来源，例如 `skill-q-platform`。
6. `checksum`：校验和，格式为 `sha256:...`。
7. `files`：安装文件元数据。
8. `compatibility`：兼容性信息。
9. `metadata`：所有者、作用域、状态、变更说明等元数据。

验收材料中对应接口为 `/api/hub/assets/[slug]/package`。

## 6. br-ai-spec 安装资产

在业务项目中使用 `br-ai-spec` 执行资产安装。V0.1 验收材料中，`hub install` 已通过本地 HTTP fixture(样例服务) 验证。

示例流程：

```bash
cd demo-project
ai-spec-auto hub install frontend-coding-standard
```

实际命令名称和参数以 `br-ai-spec` 当前 CLI(命令行工具) 为准。

## 7. 生成 manifest / lock

安装后，`br-ai-spec` 负责生成或更新：

1. `.ai-spec/manifest.json`
2. `.ai-spec/lock.json`
3. `.agents/registry/hub-lock.json`

这些文件用于锁定已安装资产版本、checksum(校验和) 和后续运行反馈中的 usedAssets(已用资产)。

## 8. 生成 Cursor / Claude Code 文件

执行同步后，`br-ai-spec` 负责生成 Cursor(开发工具) 与 Claude Code(开发工具) 适配文件。

V0.1 验收材料已记录 `sync.test.js` 覆盖：

1. `.cursor/commands`
2. `.claude/commands`

## 9. 执行最小 Run

在业务项目中执行一次最小 Run(运行)，目标不是扩展复杂功能，而是验证运行态闭环。

最小 Run(运行) 应产生：

1. runId(运行标识)。
2. projectId(项目标识)。
3. stage(阶段)。
4. status(状态)。
5. Hook/Test/Repair/Review(钩子/测试/修复/评审) 摘要。
6. changedFiles(变更文件) 相对路径和摘要。

注意：不允许把完整源码、原始 Prompt(提示词)、原始响应、绝对路径或密钥写入上报数据。

## 10. 上报 RunEvent / EvidenceReport

`br-ai-spec` 通过 Visual Connector(可视化连接器) 上报：

1. RunEvent(运行事件)：包含 eventId、runId、projectId、eventType、stage、status、severity、message、timestamp、metadata。
2. EvidenceReport(证据报告)：包含 runId、projectId、changedFiles、testResults、hookResults、repairResults、reviewResults、finalStatus。

`br-ai-spec-visual` 的 Collector API(采集接口) 接收：

1. POST `/api/collector/run-event`
2. POST `/api/collector/evidence-report`
3. GET `/api/collector/run-event?runId=...&projectId=...`

## 11. Visual 查看 Timeline

启动 `br-ai-spec-visual` 后，在 Visual(可视化) 中查看运行态：

```bash
cd br-ai-spec-visual
pnpm install
pnpm dev
```

V0.1 关注以下视图：

1. Run Timeline(运行时间线)。
2. Hook/Test/Repair/Review(钩子/测试/修复/评审) 结果。
3. Agent(代理) 协作。
4. Metrics(指标)。
5. Risk(风险)。

当前 Collector Store(采集存储) 为内存存储，重启服务后数据不会作为长期历史保留。

## 12. 回传 AssetUsageFeedback

Run(运行) 完成后，回传 AssetUsageFeedback(资产使用反馈) 到 Hub(资产中心)。V0.1 反馈字段包括：

1. feedbackId(反馈标识)。
2. assetId(资产标识)。
3. assetType(资产类型)。
4. runId(运行标识)。
5. projectId(项目标识)。
6. status(状态)。
7. metrics(指标)：adopted(已采纳)、hookBlocked(钩子阻塞)、testPassed(测试通过)、repairSucceeded(修复成功)、manualIntervention(人工介入)。
8. timestamp(时间戳)。

验收材料中对应接口为 POST `/api/hub/assets/feedback`。

## 13. Hub 查看质量指标

`skill-q-platform` 接收反馈后，可查看资产质量指标：

1. usageCount(使用次数)。
2. successRate(成功率)。
3. failureRate(失败率)。
4. adoptionRate(采纳率)。
5. riskScore(风险分)。
6. qualityScore(质量分)。

验收材料中对应接口为 GET `/api/hub/assets/[slug]/quality`。

## 14. V0.1 最小试点清单

试点时只跑以下内容：

1. asset search(资产搜索)。
2. asset install(资产安装)。
3. manifest(清单) / lock(锁文件) 生成。
4. Cursor(开发工具) / Claude Code(开发工具) 文件生成。
5. RunEvent(运行事件) / EvidenceReport(证据报告) 上报。
6. Visual(可视化) 查看 Timeline(时间线)。
7. AssetUsageFeedback(资产使用反馈) 回传。
8. Hub(资产中心) 查看质量指标。
