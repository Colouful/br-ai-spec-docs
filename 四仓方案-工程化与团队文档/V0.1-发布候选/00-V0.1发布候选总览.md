# V0.1 发布候选总览

## 1. 项目定位

V0.1 发布候选的定位是：把企业级 AI 研发控制平面从设计阶段收口到可验收、可冻结、可试点的四仓方案。

本阶段不继续扩展产品功能，重点是统一文档、冻结版本边界、承接真实联调结论，并为后续团队试点提供一致入口。

## 2. 四仓职责

| 仓库 | 职责 |
| --- | --- |
| `br-ai-spec` | 本地 CLI(命令行工具) 与执行控制面，负责资产安装、manifest(清单) / lock(锁文件) 生成、Cursor(开发工具) / Claude Code(开发工具) 文件生成、RunEvent(运行事件) 和 EvidenceReport(证据报告) 输出、Visual Connector(可视化连接器)、Hub Connector(资产中心连接器)、Schema(模式) 和 Fixture(样例数据)。 |
| `br-ai-spec-visual` | 运行态观测面，负责 Collector API(采集接口)、RunEvent(运行事件) 接收、EvidenceReport(证据报告) 接收、Run Timeline(运行时间线)、Hook/Test/Repair/Review(钩子/测试/修复/评审) 展示、Agent(代理) 协作展示、质量指标、风险审计摘要和 PrivacyGuard(隐私守卫)。 |
| `skill-q-platform` | Asset Hub(资产中心)，负责资产模型、搜索、详情、AssetPackage(资产包)、版本、回滚、审核发布废弃、Fork(派生) / Override(覆盖) / 继承、AssetUsageFeedback(资产使用反馈) 和资产质量评分。 |
| `br-ai-spec-docs` | 文档中心，负责四仓边界、验收报告、架构说明、团队上手、已知问题、发布检查清单和历史文档关系说明。 |

## 3. 当前完成能力

### 3.1 br-ai-spec

1. P0-P3 能力收口已完成。
2. Visual Connector(可视化连接器) 已完成：支持 RunEvent(运行事件)、EvidenceReport(证据报告)、脱敏、失败队列和非阻塞上报。
3. Hub Connector(资产中心连接器) 已完成：支持资产搜索、安装、同步、升级、回滚和运行反馈上报。
4. Schema Export(模式导出) 和 Fixture(样例数据) 已完成。
5. `contracts/schemas` 与 `contracts/fixtures` 已输出 RunEvent(运行事件)、EvidenceReport(证据报告)、AssetPackage(资产包)、Manifest(清单)、AssetUsageFeedback(资产使用反馈)。

### 3.2 br-ai-spec-visual

1. Collector API(采集接口) 已完成。
2. RunEvent(运行事件) 与 EvidenceReport(证据报告) 接收已完成。
3. Run Timeline(运行时间线)、Hook/Test/Repair/Review(钩子/测试/修复/评审)、Agent(代理) 协作展示已完成。
4. 质量指标和风险审计摘要已完成。
5. PrivacyGuard(隐私守卫) 已覆盖源码、原始提示词、原始响应、绝对路径、密钥等敏感信息拦截。

### 3.3 skill-q-platform

1. Asset Hub(资产中心) 基础模型已完成。
2. 资产搜索、资产详情、AssetPackage(资产包) 元数据已完成。
3. 版本列表、回滚元数据已完成。
4. 审核、发布、废弃链路已完成。
5. Fork(派生) / Override(覆盖) / 继承已完成。
6. AssetUsageFeedback(资产使用反馈) 与资产质量评分已完成。

### 3.4 四仓联调

1. I1：资产发布到安装，通过。
2. I2：运行上报到 Visual，通过。
3. I3：资产质量反馈闭环，通过。
4. I4：文档同步与最终验收，通过；正式目标路径曾记录为待确认，本轮在当前文档仓库完成收口。

## 5. 四仓联调结论

四仓联调 I1-I4 已完成。验收材料记录的真实方式包括：

1. `br-ai-spec` 使用本地 HTTP fixture(样例服务) 验证 Hub(资产中心) 安装、锁文件、IDE(开发工具) 输出和运行反馈上报。
2. `br-ai-spec-visual` 使用 Next.js Route Handler(路由处理器) 集成测试验证 Collector API(采集接口)、RunEvent(运行事件)、EvidenceReport(证据报告) 和展示数据模型。
3. `skill-q-platform` 使用 Route Handler(路由处理器) 和内存事务仓储验证 active Rule(启用规则) 发布、搜索、AssetPackage(资产包)、反馈回传和质量评分更新。

本发布候选不伪造常驻服务测试结果；未启动的长驻 dev 服务不写成已通过。

## 7. V0.1 使用边界

V0.1 适合做团队内候选验收和小范围真实项目试点，建议只跑以下闭环：

1. asset search(资产搜索)。
2. asset install(资产安装)。
3. manifest(清单) / lock(锁文件) 生成。
4. Cursor(开发工具) / Claude Code(开发工具) 文件生成。
5. RunEvent(运行事件) / EvidenceReport(证据报告) 上报。
6. Visual(可视化) 查看 Timeline(时间线)。
7. AssetUsageFeedback(资产使用反馈) 回传。
8. Hub(资产中心) 查看质量指标。

V0.1 不适合承诺组织级大规模生产推广；需要先通过真实业务项目试点收集反馈。
