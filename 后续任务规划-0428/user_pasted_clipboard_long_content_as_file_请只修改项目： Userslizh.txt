## 一、本轮目标

本轮目标是把 P5 阶段的 Review Workflow 审核流程从历史内存路径升级为统一事务化路径。

必须保证：

1. Asset Version 的 submit-review / reject / publish 读写同源。
2. Manifest Version 的 submit-review / reject / publish 读写同源。
3. Agent Profile 的 submit-review / reject / publish 读写同源。
4. 所有状态变更和 AuditLog 写入处于同一事务。
5. `HUB_REPOSITORY_MODE=memory` 时读写都走 memory。
6. `HUB_REPOSITORY_MODE=prisma` 时读写都走 Prisma。
7. 不允许出现读 prisma、写 memory 的混用。
8. 不允许 AuditLog 成功但业务状态失败。
9. 不允许业务状态成功但 AuditLog 失败。
10. 保持 V1.1 Hub API、V2.1 页面、P3.3、P3.4、P3.5 不被破坏。

## 七、状态流转规则

必须保持 P5 规则：

```text
draft -> reviewing
rejected -> reviewing
reviewing -> rejected
reviewing -> published
published -> deprecated
published -> archived
deprecated -> archived
```

本轮重点实现：

```text
draft/rejected -> reviewing
reviewing -> rejected
reviewing -> published
```

要求：

1. 只有 draft / rejected 可以 submit-review。
2. 只有 reviewing 可以 reject。
3. 只有 reviewing 可以通过审核发布。
4. publish 是否继续兼容 draft 直接发布，按现有 P1/P2/P3 兼容策略保留；但 Review Workflow 主路径必须是 reviewing -> published。
5. published / deprecated / archived 不允许 submit-review。
6. archived 不允许任何审核流操作。
7. reject 必须填写 reason。
8. 所有非法状态必须返回中文错误。

## 十、AuditLog 写入规则

submit-review 成功时写入：

```ts
{
  targetType,
  targetId,
  action: "submit-review",
  statusFrom: "draft" 或 "rejected",
  statusTo: "reviewing",
  operatorId: "system",
  operatorName: "系统",
  operatorType: "system",
  note
}
```

reject 成功时写入：

```ts
{
  targetType,
  targetId,
  action: "reject",
  statusFrom: "reviewing",
  statusTo: "rejected",
  operatorId: "system",
  operatorName: "系统",
  operatorType: "system",
  reason
}
```

publish 成功时：

1. 如果领域发布服务已写入 `action=publish`，不要重复写。
2. 如果领域服务未写入，则必须在同一事务内写入。
3. 不允许一条 publish 操作产生重复 AuditLog。
