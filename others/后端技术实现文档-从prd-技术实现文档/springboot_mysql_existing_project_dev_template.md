# 5. 改造原则与总体策略

## 5.1 改造原则

1. 最小侵入：优先新增扩展点，不轻易修改核心主流程。
2. 兼容优先：旧接口、旧数据、旧调用方必须保持可用。
3. 复用优先：优先复用现有 Service、Mapper、枚举、工具类、错误码。
4. 可灰度：必要时通过配置开关控制新逻辑是否启用。
5. 可回滚：出现问题时能关闭新能力或回退版本。
6. 可测试：每个接口必须有 Apifox 测试用例。
7. 可追踪：关键操作必须有日志、操作人、业务标识。

# 7. 技术方案设计

## 7.1 方案概览

本次需求采用如下技术方案：

1. 在现有模块中新增 / 修改相关接口。
2. 复用现有业务校验逻辑。
3. 新增必要的数据字段 / 数据表。
4. 新增 Apifox 单接口用例与场景用例。
5. 通过灰度开关或版本回退保障上线安全。

## 7.2 业务流程设计

### 7.2.1 主流程

```text
客户端 / 前端发起请求
  ↓
Controller 接收请求
  ↓
参数校验
  ↓
权限校验
  ↓
Service 执行业务规则校验
  ↓
查询 / 写入数据库
  ↓
记录业务日志
  ↓
返回响应
```

### 7.2.2 异常流程

| 异常场景 | 触发条件 | 处理方式 | 返回错误码 |
|---|---|---|---|
| 参数缺失 | 必填参数为空 | 返回参数错误 | 400001 |
| 数据不存在 | 根据 ID 查询为空 | 返回业务错误 | 400404 |
| 状态不允许 | 当前数据状态不可操作 | 返回业务错误 | 400409 |
| 无权限 | 当前用户无操作权限 | 返回无权限 | 403001 |
| 数据库异常 | SQL 执行失败 | 记录日志并返回系统错误 | 500001 |

### 7.2.3 状态流转

| 当前状态 | 操作 | 目标状态 | 说明 |
|---|---|---|---|
| INIT | 提交 | PROCESSING | 进入处理中 |
| PROCESSING | 成功 | SUCCESS | 处理完成 |
| PROCESSING | 失败 | FAILED | 处理失败 |
| FAILED | 重试 | PROCESSING | 重新处理 |

| 新增索引 | 如影响写入性能，可单独评估删除 |
| 迁移数据 | 提供反向修复脚本 |

# 9. 接口设计

## 9.1 接口设计原则

1. 优先新增接口，避免修改旧接口影响调用方。
2. 如必须修改旧接口，只允许新增可选字段，不允许修改原字段含义。
3. 所有接口必须有统一响应结构。
4. 所有接口必须有错误码。
5. 所有写接口必须考虑幂等。
6. 所有接口必须设计 Apifox 测试用例。

## 9.2 统一响应结构

```json
{
  "code": 0,
  "message": "成功",
  "data": {}
}
```

## 9.3 错误码设计

| 错误码 | 含义 | 触发场景 |
|---|---|---|
| 0 | 成功 | 请求成功 |
| 400001 | 参数错误 | 必填参数为空或格式错误 |
| 400404 | 数据不存在 | 查询对象不存在 |
| 400409 | 状态冲突 | 当前状态不允许操作 |
| 403001 | 无权限 | 当前用户无权限 |
| 500001 | 系统异常 | 未知系统错误 |

## 9.4 新增接口一：创建 XXX

### 基本信息

| 项目 | 内容 |
|---|---|
| 接口名称 | 创建 XXX |
| URL | `/api/xxx/create` |
| Method | POST |
| Content-Type | application/json |
| 是否新增接口 | 是 |
| 是否影响旧接口 | 否 |
| 是否需要登录 | 是 |
| 是否需要权限 | 是 |
| 是否需要幂等 | 是 |

### 请求参数

```json

  "remark": "备注信息"

```

### 请求参数说明

| 参数 | 类型 | 是否必填 | 说明 | 校验规则 |
|---|---|---|---|---|
| name | string | 是 | 名称 | 长度 1-64 |
| type | string | 是 | 类型 | 枚举：DEFAULT / CUSTOM |
| remark | string | 否 | 备注 | 最大 255 字符 |

### 返回示例


# 10. Service 与事务设计

## 10.1 Service 方法设计

| 方法名 | 入参 | 返回值 | 职责 |
|---|---|---|---|
| createXxx | XxxCreateDTO | XxxVO | 创建业务数据 |
| updateXxx | XxxUpdateDTO | Boolean | 更新业务数据 |
| queryXxxDetail | Long id | XxxVO | 查询详情 |

## 10.2 事务边界

| 方法 | 是否开启事务 | 事务范围 | 说明 |
|---|---|---|---|
| createXxx | 是 | 参数校验后到数据库写入完成 | 避免把外部接口调用放入事务 |
| updateXxx | 是 | 状态校验与更新 | 保证状态一致 |
| queryXxxDetail | 否 | 只读 | 不需要事务 |

## 10.3 事务注意事项

1. 避免大事务。
2. 避免在事务内调用外部系统。
3. 避免事务内执行长耗时循环。
4. 批量处理建议分批提交。
5. 异步任务与主事务分离。

```java
    // 5. 写入数据库
    // 6. 记录操作日志
    // 7. 返回结果
}
```

# 19. 回滚方案

## 19.1 应用回滚

1. 关闭功能开关。
2. 回退到上一稳定版本。
3. 重启服务。
4. 验证旧接口可用。
5. 执行旧接口回归。

## 19.2 数据库回滚

| 数据库变更 | 回滚方式 | 说明 |
|---|---|---|
| 新增字段 | 默认保留 | 避免删字段造成风险 |
| 新增表 | 默认保留 | 不影响旧逻辑 |
| 新增索引 | 如影响性能可删除 | 需 DBA 评估 |
| 迁移数据 | 执行反向脚本 | 必须提前准备 |

## 19.3 回滚验证

| 验证项 | 标准 |
|---|---|
| 服务启动 | 无启动异常 |
| 旧接口 | 可正常访问 |
| 旧数据 | 可正常查询 |
| 新逻辑 | 已关闭或不可访问 |
| 日志 | 无持续异常 |
