# 大型金融中台新组件库迁移综合方案 v2

## 1. 最终判断

本项目不建议只输出普通文档，也不建议直接让 AI 全局替换组件。

最终推荐方案：

> **Skill 为主，文档为辅，Page2 影子迁移为执行策略，returnCallList 为样板页面，分批灰度推进。**

原因：

1. 金融中台迁移的核心风险不是组件替换本身，而是业务逻辑、权限逻辑、API 参数、分页排序、表单校验、导出批量操作等隐性行为被破坏。
2. Skill 可以约束 AI/Codex 的执行边界，文档只能说明原则，不能稳定限制执行行为。
3. Page2 可以让原页面与迁移页面并行存在，便于对比、测试、回滚和验收。
4. 已有 returnCallList 样板页覆盖三类关键场景：主列表页、弹窗内嵌表格、新增/编辑表单弹窗，适合作为迁移母版。
5. @ex/ux-comp 支持 Vue 3、Arco 默认入口、Pro 系列业务组件、按需导入、全局 ProProviders 配置，适合企业级中后台统一组件替换。

---

## 2. 推荐交付形态

### 主交付物：Component Migration Skill

用于给 Codex / AI 执行迁移任务，内置强约束：

- 不修改原页面
- 不修改业务逻辑
- 只在 Page2 迁移
- 先盘点再改代码
- 改完必须测试
- 输出验收报告
- 遇到共享逻辑/权限逻辑/接口语义不清必须停下来

### 辅助交付物

| 交付物 | 用途 |
| --- | --- |
| 迁移战略文档 | 给人理解整体策略 |
| 页面盘点模板 | 每个页面迁移前先冻结现状 |
| 组件映射模板 | 记录旧组件到新组件的映射 |
| 边界逻辑登记表 | 防止空值、日期、金额、权限等行为被改坏 |
| Page1/Page2 对比表 | 验证迁移前后业务行为一致 |
| 测试矩阵 | 约束测试覆盖 |
| 验收报告 | 决定是否进入下一批迁移 |
| Codex 执行提示词 | 让 AI 按 Skill 规则执行 |

## 3. Page2 影子迁移策略

### 3.1 基本路径

原页面保持不动：

```text
src/views/module/page/index.vue
```

新增迁移页：

```text
src/views/module/page2/index.vue
src/views/module/page2/setting.js
src/views/module/page2/components/*
```

### 3.2 允许修改

- Page2 目录下文件
- Page2 路由
- Page2 测试入口
- Page2 局部样式
- Page2 局部 adapter

### 3.3 禁止修改

- 原页面
- 共享 API 文件
- store
- router 业务逻辑
- 权限判断逻辑
- 全局 hooks
- 后端参数语义
- 表单校验意图
- 导出、批量操作参数语义

## 4. 技术路线

### 4.1 组件选择优先级

1. `@ex/ux-comp` Pro 组件
2. `@arco-design/web-vue` 作为兜底
3. 禁止继续使用 `@koi-design/*`

### 4.2 主要映射

| 旧实现 | 新实现 | 注意点 |
| --- | --- | --- |
| `DynamicsFilter + u-table` | `ProTable` | 搜索和表格合并到 columns |
| `usePageList` | `ProTable.request` | 参数签名必须适配，不改 API 语义 |
| `useStorageQuery` | `queryData + sessionStorage adapter` | 查询缓存不能丢 |
| `ColumnsSetting` | ProTable 内置列设置 | 不额外实现重复功能 |
| `UModal + DynamicsForm` | `ProModalForm type="modal"` | rules、初始值、回填时机要保持 |
| `EditDrawer` | `ProModalForm type="drawer"` | 抽屉生命周期要对齐 |
| `ViewContent / OneLineText` | `ProDescriptions` | 空值和 formatter 要对齐 |
| 多个 `u-link/u-tooltip` | `ProActions type="link"` | 权限显隐、禁用态、二次确认要对齐 |
| 简单按钮/链接/弹窗 | Arco 组件 | 作为 Pro 组件不覆盖场景的降级方案 |

## 5. 分阶段执行计划

### 阶段 0：迁移基线确认

目标：先确认组件库和项目入口策略。

产出：

- 组件库版本确认
- Arco 默认入口确认
- 全量样式 or 按需样式策略
- ProProviders 是否全局接入
- 参考页面 returnCallList 固化为样板

建议：

优先使用按需引入；如果项目已有全量样式入口，则全局引入 `@ex/ux-comp/style.arco.css`，再逐步优化到按需。

### 阶段 1：页面分级

按风险分三类：

#### A 类：低风险样板页

- 普通列表
- 搜索字段少
- 操作简单
- 无复杂权限
- 无金额/账务/审批

用于第一批试点。

#### B 类：中风险业务页

- 有复杂搜索
- 有弹窗表单
- 有导出/批量
- 有权限按钮

用于第二批。

#### C 类：高风险金融核心页

- 审批
- 放款
- 账务
- 还款
- 风控
- 资产处置
- 合同
- 费用/金额计算

最后迁移，必须有人工验收。

### 阶段 2：单页 Page2 迁移

每个页面按这个流程：

1. 盘点原页面
2. 复制 Page2
3. 确认 Page2 未迁移前可打开
4. 迁移搜索 + 表格
5. 迁移操作列
6. 迁移工具栏
7. 迁移弹窗/抽屉
8. 迁移详情/空态
9. 做 Page1/Page2 对比
10. 完成验收报告

### 阶段 3：样板固化

第一批页面完成后，沉淀：

- 统一 adapter
- 日期范围处理模板
- 查询缓存模板
- ProTable request 模板
- ProModalForm 编辑回填模板
- 权限按钮 ProActions 模板
- 测试脚本模板

### 阶段 4：批量迁移

每批建议 3-5 个页面，不要一次全量铺开。

每批必须有：

- 批次计划
- 风险评级
- 页面清单
- 测试结果
- 回滚方案
- 验收结论

## 6. 测试策略

### 6.1 静态测试

```bash
# 原页面不能有 diff
git diff -- src/views/原页面路径

# Page2 不能有 Koi import
grep -R "@koi-design" src/views/页面2路径 || true

# Page2 不能残留旧组件
grep -R "DynamicsFilter\|DynamicsForm\|EditDrawer\|ColumnsSetting\|ViewContent\|OneLineText" src/views/页面2路径 || true

# Page2 不能残留 u-* 标签
grep -R "<u-" src/views/页面2路径 || true
```

### 6.2 功能测试

必须覆盖：

- 页面打开
- 首次请求
- 搜索
- 重置
- 分页
- pageSize
- 排序
- 行选择
- 批量操作
- 权限按钮
- 新增弹窗
- 编辑弹窗
- 表单校验
- 表单提交失败不关闭
- 详情跳转
- 导出下载
- 空数据
- 接口失败
- loading
- 无权限账号

### 6.3 对比测试

Page1 与 Page2 同时验证：

| 场景 | 重点 |
| --- | --- |
| 搜索 | 请求参数是否一致 |
| 重置 | 默认值和页码是否一致 |
| 分页 | pageNo/pageSize 是否一致 |
| 排序 | sortField/sortType 是否一致 |
| 权限 | 按钮显隐是否一致 |
| 表单 | 初始值、回填、校验是否一致 |
| 导出 | 导出参数是否一致 |
| 批量 | selectedRowKeys 是否一致 |

## 7. 验收标准

一个页面只有满足以下条件才能算完成：

- 原页面无改动
- Page2 可访问
- Page2 无 Koi import
- Page2 无旧组件残留
- 业务 API 参数语义未变
- 权限行为未变
- 搜索/表格/表单/导出/批量核心路径通过
- 边界逻辑已登记
- Page1/Page2 对比已完成
- 验收报告已输出

---

## 8. 最终建议

### 我建议你下一步这样做

1. 不要再纠结“文档还是 Skill”：主方案就是 Skill。
2. 把当前 Skill 升级成“金融中台 Page2 迁移 Skill”。
3. 把 returnCallList 作为第一样板。
4. 选 1 个真实业务页面做第二样板。
5. 第二样板跑通后，再进入 3-5 页一批的节奏。
6. 所有迁移必须强制产出测试矩阵和验收报告。
7. C 类高风险页面不要交给 AI 直接全自动完成，必须加人工验收门禁。

最终一句话：

> 这个项目的成功关键不是组件替换速度，而是建立一套 AI 不敢乱动业务逻辑、开发可复用、测试可验收、失败可回滚的迁移体系。
