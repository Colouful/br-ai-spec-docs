# br-ai-spec-docs

本仓库是企业级 AI 研发控制平面四仓方案的文档中心，负责沉淀标准、架构说明、联调验收、团队上手和历史资料索引。

当前最新文档基线为：**V0.1 发布候选**。

> 说明：如果旧文档、历史资料或早期快速上手说明与 V0.1 发布候选文档冲突，以 `四仓方案-工程化与团队文档/V0.1-发布候选/` 下的文档为准。旧文档保留为历史上下文，不再代表当前实现边界。

## 四仓职责边界

| 仓库 | 当前职责 |
| --- | --- |
| `br-ai-spec` | 本地 CLI(命令行工具)、项目初始化、资产安装、manifest(清单) / lock(锁文件) 生成、Cursor(开发工具) / Claude Code(开发工具) 文件生成、Visual Connector(可视化连接器)、Hub Connector(资产中心连接器)、Schema(模式) 与 Fixture(样例数据) 输出。 |
| `br-ai-spec-visual` | Collector API(采集接口)、RunEvent(运行事件) 接收、EvidenceReport(证据报告) 接收、Run Timeline(运行时间线)、Hook/Test/Repair/Review(钩子/测试/修复/评审) 展示、Agent(代理) 协作展示、质量指标、风险审计摘要、PrivacyGuard(隐私守卫)。 |
| `skill-q-platform` | Asset Hub(资产中心)、资产搜索、资产详情、AssetPackage(资产包) 元数据、版本列表、回滚元数据、审核发布废弃、Fork(派生) / Override(覆盖) / 继承、AssetUsageFeedback(资产使用反馈)、资产质量评分。 |
| `br-ai-spec-docs` | 四仓方案文档中心，负责标准说明、验收报告、团队操作手册、版本发布检查清单和历史文档关系说明。 |

## V0.1 已完成能力

1. `br-ai-spec` 已完成 P0-P3 能力收口、Visual Connector(可视化连接器)、Hub Connector(资产中心连接器)、Schema Export(模式导出)、Fixture(样例数据) 输出以及 `contracts/schemas`、`contracts/fixtures` 契约目录。

3. `skill-q-platform` 已完成 Asset Hub(资产中心) P5 能力：资产包、版本、回滚、继承、反馈和质量评分。
4. 四仓联调 I1-I4 已完成：资产发布到安装、运行上报到 Visual、资产质量反馈闭环、文档同步与最终验收。

## 推荐阅读顺序

1. 先读 `00-V0.1发布候选总览.md`，确认当前版本能做什么、不能做什么。
2. 再读 `02-四仓最终架构说明.md`，确认四仓边界和链路。
3. 然后读 `03-团队快速上手指南-V0.1.md`，按最小闭环执行。
4. 准备验收或发布时读 `01-四仓联调最终验收报告.md` 与 `05-V0.1发布检查清单.md`。
5. 规划后续工作时读 `04-已知问题与后续路线.md`。

## 旧文档和新文档的关系

本仓库保留大量历史资料，包括早期三仓 PRD(产品需求文档)、Manifest(清单) 链路说明、Hub(资产中心) 草案、Visual(可视化) 草案和旧快速上手指南。这些资料用于理解设计演进，不应直接作为 V0.1 当前操作依据。

已标记为历史版本的旧文档：

- `四仓方案-工程化与团队文档/团队成员阅读的精简版项目介绍文档/快速上手指南.md`

当前目标仓库执行本阶段前未发现该旧快速上手正文，因此上述文件只记录历史提示和最新文档入口，未伪造旧内容。

历史文档仍可阅读，但如果出现以下冲突，以 V0.1 发布候选文档为准：

1. 旧文档说 Visual(可视化) 只扫描业务项目展示 Manifest(清单)，而当前实现已经进入 RunEvent(运行事件) / EvidenceReport(证据报告) 上报与 Timeline(时间线) 展示链路。
2. 旧文档只描述 Manifest(清单) 发布和安装，而当前实现已经包含 AssetPackage(资产包)、AssetUsageFeedback(资产使用反馈) 和质量评分闭环。
3. 旧文档把部分能力放在单仓说明中，而当前 V0.1 已按四仓职责边界冻结。

## 维护要求

1. 新增或修订文档必须使用中文。
2. 不允许伪造测试结果；未执行的命令只能标记为待确认。
3. 不删除历史文档，除非有明确归档计划。
4. 不提交 `node_modules`、日志、缓存、`.env` 或本机状态目录。
